## 维护规则

1. **一行一票、一次一改**：状态变更只触碰该票行的「状态/领取/修复commit/验收证据」列。
2. 领取即落标：③ 方案确认后立刻改行 + 本地 commit，推送须问用户（建议推——防别机撞票）。
3. 验收通过后：状态→`已验收待关单`，证据列填 `evidence/bug{ID}/` 路径，随 commit 提交。
4. **禅道关单由人在禅道操作**（库仅本机 docker），本表最多标到「已验收待关单」；关单后回填「已关单」。
5. push 时发现队列同行冲突 = 撞票：fetch 对比，后到者弃票改下一张，本地已做 commit 保留待用户裁决。
6. 新一批 bug 入列：走 skill（`/bug-fix`）「材料包入列」节（`/bug-fix <材料包路径>`）——落位 `water-erp/docs/bugs/<日期>-<负责人>/`、大图压缩改引用、建队列沿用本文件格式。
