## 一、A 组逐条复核

### A1. 后端没有「门户」概念 —— ✅ 主体解决（fcf8f6dc），⚠️ 附两处回归

**原结论**：:3005 与 :3007 后端同门户（X-Portal: web + token_web），任何 bid_host 从 :3005 都能调 start-evaluation/decrypt/签字包端点。

**当前代码**：

- 门户角色表：`apps/api/src/auth/port-roles.ts:9-24` —— `PORT_ALLOWED_ROLES`（public/web/expert/bid/mall/supplier 六门各允许集）
- **L3 登录校验**：`auth.controller.ts:83-87` —— login 时角色不在当前门户允许列表 → 403
- **L4 运行时校验**：`auth.guard.ts:39-44` —— 每次请求验 JWT 后角色-端口不匹配 → 403
- **L5 路径白名单**：`app.module.ts:107-113` 全局守卫链 `AuthGuard → PortRouteGuard → RolesGuard → ThrottlerGuard`（顺序正确）；`port-routes.ts:64-87` `BID_EXCLUSIVE_PATTERNS` 精确覆盖 start-evaluation/decrypt/scores/score-records/clarifications/disputes/result/sign/sign-packet/complete-opening 等现场执行端点
- **L6 数据隔离**：`bid.service.ts:168,221`（列表按 portal 过滤）、`:379-380`（detail 非指派 403）、`:408-409`（`sanitizeForBidHost` 字段去敏）
- :3007 独立门户实体化：`apps/bid-portal/src/proxy.ts:13-14` `PORTAL='bid'` + token_bid + X-Portal: bid

**复核结论**：原痛点已堵死——bid_host 从 :3005 调 start-evaluation/decrypt/sign-packet → portal=web 命中 BID_EXCLUSIVE → 403；事实上 bid_host **连登录 :3005 都不再可能**（L3，见 A6）。

**⚠️ 引入的回归**：

- **R1（监督锁出）**：`bid.service.ts:379-380` 对 portal=bid 的**所有角色**按 `assignedHostUserId` 过滤——leader/staff/admin 若非开标主持人，打不开项目工作区（含监督视图 tab）。监督者与主持人本就是两个人，这条直接推翻监督场景。**需要产品决策**：对 admin/leader 豁免，或只对 bid_host 按指派过滤。
- **R2（任务板空板）**：`bid.service.ts:168,221` 列表接口同规则——admin 未被指派时 :3007 任务板/统计可能一片空白。

**建议**：L6 过滤条件改为「portal=bid 且 role=bid_host 才按指派过滤」，或引入监督指派字段。

### A2. :3007 中间件角色缺口 + 三处手工同步 —— 🟡 部分解决

**原结论**：:3007 proxy 允许 leader/staff（与「现场端=主持人/admin」矛盾），三处角色数组靠注释手工同步；:3005 proxy 完全不做角色校验。

**当前代码**：

- `apps/bid-portal/src/proxy.ts:38` `ALLOWED_ROLES = ['admin','bid_host','leader','staff']` —— **原样未收紧**；fcf8f6dc 删除了原「与 bid.controller @Roles 保持一致」的同步注释（`git show fcf8f6dc`）
- `apps/web/src/proxy.ts` 仍零角色校验（grep role/allowed 无果）——但被后端 L3/L4 兜底：无 token_bid 的 :3005 请求带 web JWT，角色不符即 403
- 专家登录页 `apps/expert-portal/src/app/login/page.tsx:28` `WEB_ROLES = ['admin','bid_host','leader','staff']`，注释仍写「与后端 portal-cookie 的 ROLE_PORTAL 对齐」（实际后端概念已变为 `PORT_ALLOWED_ROLES.expert`）

**复核结论**：中间件层面的缺口已被后端四层兜底；「现场端=主持人/admin」的语义收紧仍未做（需产品拍板）。角色数组现在是**四处**：`PORT_ALLOWED_ROLES.bid/.expert`（后端）+ bid proxy `ALLOWED_ROLES` + expert login `WEB_ROLES` + `bid.controller` 各端点 `@Roles`。手工同步问题从三处变四处。

**建议**：前端数组改为只做「有无 token」检查，角色不匹配交给后端 403 处理（前端统一拦截 `PORT_ROLE_MISMATCH`/`PORT_ROUTE_FORBIDDEN` 错误码跳转），消除两份前端数组。
