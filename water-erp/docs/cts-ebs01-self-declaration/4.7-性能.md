# 4.7 性能自声明素材

## 已具备（代码事实）
- 连接池：docker-compose `pgbouncer`（API 走 6432 池化，迁移 5432 直连），postgres 可纵向扩容
- 异步解耦：AI 分析走 BullMQ 队列（Redis），worker 完全无状态、多开即扩容（docs/ops-scaling.md 有 2 万人规模 Runbook：`AI_BID_WORKER_CONCURRENCY` 可调）
- 对象存储：MinIO 独立服务，文件 IO 与主库分离
- 开标实时：WebSocket 网关（bid.gateway）独立于 HTTP 请求路径
- 投标文件加解密为流式（streamToBuffer + AES 分段），大文件不受请求体限制阻塞

## 附录：实测压测记录（2026-08-25，开发机 macOS / Node24 单进程 / Postgres 容器）

压测方式：node fetch 并发循环（无外部依赖脚本），认证态 GET，限流经 `THROTTLE_LIMIT` 临时放开（生产默认 120 次/分钟已验证会拦截，见 4.8）。

| 场景 | 并发 | RPS | p50 | p95 | p99 |
|---|---|---|---|---|---|
| 项目管理列表 | 20 | 1122 | 18ms | 24ms | 29ms |
| 归档卷台账 | 20 | 2416 | 8ms | 10ms | 12ms |
| 供应商列表 | 20 | 1769 | 11ms | 14ms | 16ms |
| 项目管理列表 | 50 | 1168 | 42ms | 54ms | 61ms |
| 项目管理列表 | 100 | 368 | 117ms | 669ms | 4.9s |

**结论**：≤50 并发时 p95 <60ms，满足常规采购业务负载；100 并发出现连接排队拐点（p99 4.9s）——单 API 进程建议承载 ≤50 并发，更高负载按 ops-scaling.md 多进程扩容（应用无状态、池化在 pgbouncer）。
