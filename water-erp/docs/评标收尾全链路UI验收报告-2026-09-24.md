## 三、发现的缺陷（已修复）

### 1. P1｜归档自动公示草稿缺公司归属 → 收尾链被公司隔离卡死
`ensureWinnerNotice`（bid.service.ts）创建 PRE_WIN_NOTICE 草稿未落 companyId/companyName；公告列表按公司硬过滤（companyScope.filter）→ 非公司经办人（即所有 staff/leader 正常使用路径）在信息发布中心**看不到**自动草稿 → 公示发不出去 → 中标通知书被 PUBLICITY_NOT_ENDED 永久阻塞。实测：API list 对 co-swhi-sjy 用户返回空；补 companyId 后立即可见。
**修复**：创建时补 `companyId: project.companyId, companyName: project.companyName`（随 1d1b3729 入库——并行会话提交顺带，内容完整）。

### 2. P2｜草稿恢复丢通过性裁定 → 全勾却「未完成」且无按钮可补
`restoreDraft` 只补全 points 映射不重导 passed：恢复后 checklist 全亮、项头却「未评」，提交被「有评分项未完成」拦截；通过性项 UI 无裁定按钮（verdict 仅展示），唯一逃生门是手动取消再勾选（触发 handlePointChange 重导）。实测复现+逃生门验证均通过。
**修复**：恢复时按 handlePointChange 同规则从客观分点重导 passed（e7f14f2c）。注：修复后 live 复测因项目已 ARCHIVED 不可入向导，以规则镜像+tsc 绿论证，建议下轮评标复验。
