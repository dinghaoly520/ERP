## 一、recreate 之前：三件同批落 B 机真身

### 1. run compose（真身，含 ai-worker/金仓——勿用仓库副本覆盖）api 服务贴挂载段

```yaml
    volumes:
      # 运行时密钥/信任锚持久化（bind mount 落 compose 同目录 ./data/api-data，活过容器重建）：
      #   admin-keystore/ 管理方外层私钥——admin-cert/generate 运行时写入；丢=对应历史信封外层永久不可解
      #   supervision/    监督推送平台签名私钥（A-153）
      #   trusted-ca/     X.509 链校验信任锚——空=跳过链闸；启用链闸时放证书+设 env（见文末）
      # 必须读写挂载（不可 :ro）：generate 要写私钥文件进去
      - ./data/api-data:/app/apps/api/.data
```

与仓库副本 `backend/docker-compose.backend-run.yml` 已落的段一致；B 机真身多出的 ai-worker/金仓连接保持原样不动。

### 2. `.env.backend` 核对清单

| 项 | 取值 | 说明 |
|---|---|---|
| `CA_PILOT_SUBJECT_IDS` | **留空** | 白名单闸=全放行（测试盾期口径，A 机现状同） |
| `SMS_DEBUG_BYPASS` | `true` | 测试期验证码 123456 直过；真发再切融易达密钥 |
| `TRUSTED_CA_DIR` | **不加** | 链闸跳过=mock 兼容期默认；启用条件见文末 |
| `COOKIE_DOMAIN` | `.scsfjt.com` | 域名四件套①：跨子域 cookie（:3006 分流写 token_bid 的前提） |
| `CORS_ORIGINS` | 全部门户子域列表 | 四件套②：ssyc / supplier- / expert- / procurement- / bid- / mobile- 全列 |
| `TRUST_PROXY` | `1` | 四件套③：反代后限流/审计 IP 不失真 |
| `NODE_ENV` | `production` | 四件套④：cookie Secure（域名 https 满足）；Swagger 关闭 |

既有必填项勿动：`JWT_SECRET`(≥32)、`KMS_SECRET`、`FIELD_ENC_SECRET`（有失配 500 前科，recreate 后过 crypto-health）、`OCR_SERVICE_URL`（按 B 机现状）。

## 二、起来后验收四连

1. **管理方证书生成**：admin 登录态 `POST /api/bid/admin-cert/generate`
2. **私钥落宿主验证**：`ls -l data/api-data/admin-keystore/`（应见 `<certId>` 文件，0600）
3. **crypto-health**：FIELD_ENC 指纹核对（前科：`ec46ce3e≠b66e039c` 500）
4. **业务冒烟**：测试盾供应商经 `https://supplier-ssyc.scsfjt.com` 绑定+投递；知识库上传解析（主操作单验证节）

## 三、链闸启用（后置，测试盾期不做）

顺序铁律「**先放证书再设 env**」：env 已设+目录空 = 空信任库 + `CERT_CHAIN_ENFORCE=true` 默认拒绝 → 绑定全挂。

```bash
mkdir -p data/api-data/trusted-ca
# 从 A 机拷 scegb_sm2.pem 或重新拉取：
curl -s -o data/api-data/trusted-ca/scegb_sm2.crt http://topca.scca.com.cn/cacert/scegb_sm2.crt
# 然后 .env.backend 加：TRUSTED_CA_DIR=/app/apps/api/.data/trusted-ca  （容器内路径）
# recreate 生效；信任锚有进程内缓存，以后换证书文件也要 recreate
```
