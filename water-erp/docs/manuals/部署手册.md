# 部署手册（water-erp）

## 环境要求
- Node 24+、pnpm workspace；Docker（postgres/pgbouncer/redis/minio）
- 宿主机 NTP 对时（chrony）——投标截止判定以服务器时钟为准
- 可选：OCR 微服务 :8100（不跑则 PDF 提取退化，中文可能乱码）

## 基础设施（docker-compose.yml）
```bash
docker compose up -d          # postgres / pgbouncer(6432) / redis / minio
```

## 应用部署
```bash
pnpm install
pnpm --filter api prisma migrate deploy     # 迁移（注意：见下方迁移纪律）
pnpm --filter api exec prisma db seed       # 按需（TRUNCATE 破坏性，仅初始化）
# API（:4001）
pnpm --filter api build && node apps/api/dist/main.js
# 前端各端口
pnpm --filter web dev            # :3005 采购管理端
pnpm --filter public-portal dev  # :3002 公共门户
pnpm --filter supplier-portal-next dev  # 供应商端
pnpm --filter expert-portal dev  # :3006 专家端
# AI 分析 worker（无状态可多开）
pnpm --filter api start:worker:ai-bid-analysis
```

## 环境变量（关键）
| 变量 | 说明 | 默认 |
|---|---|---|
| DATABASE_URL | PG 连接（API 走 pgbouncer 6432） | — |
| THROTTLE_LIMIT / THROTTLE_TTL_MS | 全局限流 | 120 / 60000 |
| AI_BID_WORKER_CONCURRENCY | worker 并发 | 2 |

## 迁移纪律（重要）
存量库有已知漂移（OperationLog 分区表等），**禁止裸跑 `prisma migrate dev`**（会要求 reset）。
新增迁移走定点配方：手写 SQL 目录 → `prisma db execute --file` → `prisma migrate resolve --applied`。

## 账号初始化
见根目录 ACCOUNTS.md（各门户账号、口令规则 `<用户名>@2026`、admin 无种子用户等）。
