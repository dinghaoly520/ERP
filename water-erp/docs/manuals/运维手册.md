# 运维手册

## 日常巡检
- `GET /api/health`；`curl :8100/health`（OCR）；`docker ps`（四容器）
- 验证码/邮件通道按需检查；磁盘：backups/（14 天滚动）与 MinIO 卷

## 备份与恢复（详见 docs/db-backup.md）
```bash
pnpm db:backup                       # 每日逻辑备份（建议 cron 03:00）
bash scripts/db-restore.sh <file>    # 生产恢复（DROP 重建）
# 临时库验证路径：createdb water_erp_restore_test → 导入 → 比对 → dropdb
```
RPO≤24h；恢复演练记录见 cts-ebs01-self-declaration/4.9（2026-08-25 全表 0 错误）。

## 扩容（详见 docs/ops-scaling.md）
- API 多进程/PM2（应用无状态，池化在 pgbouncer）；压测参考 4.7：单进程 ≤50 并发
- AI worker 多开即扩（BullMQ 确定性 job ID 去重）

## 常见故障处置
| 症状 | 处置 |
|---|---|
| :3005 全站 500 | 多为 .next 缓存：停服→清 .next/dev/cache→根目录重启（运行中勿 rm -rf .next） |
| 接口 500 且涉及新字段 | 迁移未落库：按部署手册「迁移纪律」补迁移 |
| PDF 中文乱码 | OCR 服务未跑：起 :8100 后重试 |
| 端口占用/orphan 进程 | lsof -tiTCP:端口 → kill；重启须脱离式 nohup |
| watch 跑旧代码 | 增量编译假成功：rm -rf dist 全量重建 |

## 安全运维
- 限流默认 120 次/分（可环境变量调）；操作日志 /api/operation-log 可查全量留痕
- 日志审计建议每周；安全审计每月（制度表见 D-3）
