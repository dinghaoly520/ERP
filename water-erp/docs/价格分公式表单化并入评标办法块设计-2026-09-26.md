## 1. 问题（现状，均已在代码定位）

1. 业务用户被迫手写 JSON（`price-config-card.tsx:147-186` textarea）——后端 `PRICE_FORMULA_OPTIONS`（`price-formula.service.ts:22-40`，注释明言「供前端下拉渲染」）从未被前端用上。
2. **语义陷阱**：留空保存 → `parsed={}`（`price-config-card.tsx:161`）→ truthy → 引擎照跑回退最低评标价法（`price-formula.service.ts:73-75` default 分支）；「停用公式回到专家手填」无出口。
3. **零校验**：`updatePriceConfig`（`bid.service.ts:4182-4208`）对值零校验（控制器内联对象类型非 class，ValidationPipe 透传——校验须落在 service，与既有 P2-17 锁定闸同位）。
4. 公式↔办法联动只存在于建项默认 `buildEvaluationDefaults`（`project-management.service.ts:292`），UI 两块割裂。

## 2. 目标形态：合并后的「评标办法与最高限价」块

```
评标办法与最高限价（一次「保存配置」提交三字段 → PATCH /bid/projects/:id/price-config，lib/api/bid.ts:476）
├─ [锁定横幅]（EVALUATING/ARCHIVED → 后端 409 PRICE_CONFIG_LOCKED，bid.service.ts:4191；不变）
├─ 行1（grid 2 列）：最高限价/控制价（元）｜ 评标办法（下拉 4 项，EVAL_METHOD_OPTIONS 不变）
├─ 行2：价格分计算方式（下拉 4 项）——办法=合格最低价法/不评分 时整区隐藏
│   ├─ 基准价偏离法｜最低评标价法｜比例法｜专家手填（停用自动计算）
├─ 参数行（仅基准价偏离法，grid 3 列数字输入，空=引擎默认）：
│   K 折扣系数（0<K≤1，默认 0.97）｜ 每 1% 偏离扣分（>0，默认 2）｜ 无惩罚区间 %（≥0，默认 0）
│   最低评标价法/比例法：无参数，各显一句算法说明（镜像 PRICE_FORMULA_OPTIONS.description）
├─ 联动提示：
│   ├─ 偏离法/比例法 且 限价未填 → 内联警示（F11 前移；后端生成时 400 CEILING_PRICE_REQUIRED 兜底不变，bid-evaluation-results.service.ts:345）
│   └─ priceItemCount===0 → 「评分项中暂无价格类项，公式暂不参与计分」（undefined 不提示）
└─ 保存配置（三字段合并脏检查）
```

### 评标办法 ↔ 价格分计算方式联动规则

| 评标办法（表单当前值） | 公式区 | 办法值变化时公式自动带出 |
|---------|--------|--------------------------|
| comprehensive 综合评估法 | 显示 | 基准价偏离法 |
| lowest_price 最低价法 | 显示 | 最低评标价法 |
| qualified_lowest_price 合格最低价法（谈判） | **隐藏** | 保存 payload 自动含 `priceFormulaConfig: null`（若存量非空；谈判模板本无价格评分项——evaluation-method.config.ts:57） |
| none 不评分 | **隐藏** | 同上自动置 null |
| 未设置（空） | 显示（回显当前实际值，独立可配） | 不动 |

- 办法值变化时**无条件**重置公式为推荐项 + toast「价格分计算方式已随评标办法调整为 X，可按需修改」——行为可预期（改办法本就该重审公式），不跟踪"是否定制过"。
- 仅改限价/参数不触碰公式。
- 映射与建项默认一致（邀请/公开→benchmark_deviation、询比/竞价→lowest_price、谈判/直接→null），不引入新口径。

### 回显规则（所见即所得=引擎实际行为）

- `priceFormulaConfig == null` → 「专家手填」
- `formulaType` 缺失/非法（含历史 `{}`）→ 回显**最低评标价法**（引擎 default 真实回退，price-formula.service.ts:73-75）；保存时写规范形态，顺带治理脏数据
- 参数键缺失 → 输入框空、placeholder=引擎默认；**保存只写显式填写的键**（config 最小化：`{formulaType, ...显式参数}`）

## 3. 后端加固（bid.service.ts updatePriceConfig，校验置于锁定闸之后、写入之前）

- `priceFormulaConfig === null` → 合法（Prisma Json? 列可空，schema:336 已核）→ 清除
- 非 null：非纯对象 / `formulaType` 缺失或 ∉ {lowest_price, benchmark_deviation, ratio} → 400 `PRICE_FORMULA_INVALID`（error 附合法值清单）
- 数值键（存在时）：`K ∈ (0,1]`、`penaltyRate > 0`、`noPenaltyRange ≥ 0`，且须为有限数 → 400 `PRICE_FORMULA_INVALID`（error 附具体键与合法区间）
- `ceilingPrice !== undefined` 时须为 ≥0 的有限数（补后端，此前仅前端）
- **无 schema 改动**；单测落 `bid.service.spec.ts` 既有 `describe('updatePriceConfig 阶段闸（P2-17）')` 旁新增 describe（构造范式同 :1432，直接复用外层 service/prisma mock）：非法 type 400 / K 越界 400 / 非对象 400 / null 清除且 update 收到 null / ceilingPrice 负数 400 / 合法保存放行

## 6. 验收用例

1. 综合评估法项目：办法切到最低价法 → 公式自动切最低评标价法 + toast；切回综合 → 自动切基准价偏离法；手选「专家手填」→ 保存 → DB `priceFormulaConfig=null`；重开回显「专家手填」。
2. 偏离法 + 限价未填 → 内联警示即时出现、填上即消；不填直接保存**可保存**（生成时后端兜底不变）。
3. 参数校验：K 填 1.5 前端拦；绕过前端直 PATCH（K=1.5 / formulaType=foo / priceFormulaConfig="x" / ceilingPrice=-1）→ 400 `PRICE_FORMULA_INVALID`；null → 200 且 update 收到 null。
4. 谈判项目：公式区不显示；存量 config 非空时保存任一字段 → payload 自动带 null。
5. 历史脏数据 `{}`：回显「最低评标价法」，保存后 DB 为规范形态 `{formulaType:'lowest_price'}`。
6. EVALUATING/ARCHIVED：全块禁用+锁定横幅不变；绕过前端 → 409（不变）。
7. 回归：`pnpm --filter api test`（新增 describe 6 用例）+ web tsc/lint + cgzxui 红牌 `--files` + 浏览器目检 1/2/4/5。
