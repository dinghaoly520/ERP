## 🔴 Critical（4 项）— 数据丢失 / 业务阻断

### C1. `closeRound` 丢失无唱标记录的供应商最终报价

**文件**: `apps/api/src/bid/bid.service.ts` L3688-3691（`closeRound` 方法 L3677-3696）
**核查**: ✓ 已逐行验证 TRUE

`closeRound(proceedToEvaluation=true)` 仅 update 已有的 BidOpeningRecord，不 create 新记录。供应商无传统唱标记录时，最终轮报价**静默丢失**。

```ts
// 当前代码（有 bug）
const existing = await this.prisma.bidOpeningRecord.findFirst({ where: { projectId, bidSupplierId: q.bidSupplierId } });
if (existing) {
  await this.prisma.bidOpeningRecord.update({ ... });
}
// 缺少 else { create } 分支
```

**影响**: 多轮报价项目中未经历传统唱标的供应商，最终轮报价不入 BidOpeningRecord → `generateEvaluationResults` 拿不到价格 → 排名错误 / bidPrice 缺失。

**修复**: 添加 else 分支创建 BidOpeningRecord；或改为 upsert。

---

### C2. `closeRound` 非事务执行

**文件**: `apps/api/src/bid/bid.service.ts` L3677-3696（整方法无 `$transaction`）
**核查**: ✓ 已逐行验证 TRUE

轮次状态更新与 N 条 BidOpeningRecord 更新不在同一事务中。中途崩溃 → 部分 supplier 价格已更新、部分未更新 → 评标基于不一致的价格。

**修复**: 将整个 closeRound 逻辑包在 `this.prisma.$transaction(async (tx) => { ... })` 中。

---

### C3. 专家端零感知多轮报价最终价格

**文件**: `apps/expert-portal/src/` 全目录

专家评分全程看不到最终轮报价金额。assist 数据展示的是初始投标价（AI 从标书提取），非最终轮报价。专家无法做价格-质量权衡判断。

**影响**: 多轮报价项目的专家评分依据与实际计入排名的价格不一致。

**修复**: 专家 assist 数据 + 评分步骤 + 评审报告中展示最终轮报价金额（来自 BidOpeningRecord.amount）。

---

### C4. `submitQuote` TOCTOU 竞态

**文件**: `apps/api/src/supplier-portal/supplier-portal.controller.ts` L480-487
**核查**: ✓ 已逐行验证 TRUE

严格一报制的 check-then-create 非原子。双 tab 并发提交时，第二条请求收到原始 Prisma 500 错误（非友好 400）。

```ts
// 当前（有竞态）
const existing = await this.prisma.bidQuote.findUnique({ ... });
if (existing) throw ...;
return this.prisma.bidQuote.create({ ... });
```

**修复**: 改为 try-create-catch，捕获 P2002 唯一约束冲突后抛 400。
