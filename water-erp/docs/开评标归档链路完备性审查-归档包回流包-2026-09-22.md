### ① 开标文件包（BID_OPENING_HANDOVER v1）

## 五、发现的问题（按严重度）

### 🔴 P1-1 四性检测与导出取件清单漂移——5 类证据件零检测

**位置**：`apps/api/src/archive/archive-check.service.ts:88-92`

检测的回流件集合：

```ts
OR: [
  { key: `bid-evaluation-handover/${bp.id}.json` },                                          // 评标完整性包（精确 key）✓
  { key: { contains: bp.id }, category: { in: ['bid_opening_handover', 'bid_sign_packet', 'bid_decrypted'] } },
]
```

而导出取件 `ARCHIVE_PICKUP_CATEGORIES`（`archive-export.service.ts:21`）有 **8 类**。不在四性检测范围的：

- `bid_evaluation_sign_handover`（**回流包本体**）
- `sign_packet_signature_page`（共签页扫描）
- `expert_sign_scan`（逐专家签字扫描）
- `opening_sign_page` / `opening_sign_scan`（开标签字页/扫描）
- `ai_bid_report`（AI 报告）
- 以及全部按引用 ID 取件的件（笔迹图 / 签到照片 / 澄清附件——key 不含项目 ID，永不被 key 分支命中）

**后果链**：检测不验这些件的哈希/可读性 → 导出时只「下载成功即入包」，**manifest 里的 sha256 是对现物新算的，不与 DB 登记值比对**（`archive-export.service.ts:201-215` 只 `storage.download` + 重新 hash）→ 被篡改/损坏的对象会被静默打进「四性检测 PASSED」的卷里，manifest 指纹反而「合法化」了篡改内容。全代码库唯一做 `fa.sha256 === digest` 比对的地方就是四性检测（`archive-check.service.ts:104`），恰好在证据链最重的这批件上是盲区。

**修复建议**：检测集合与 `ARCHIVE_PICKUP_CATEGORIES` 统一为单一常量源（防再漂移——两清单已有 `archive-pickup-categories.spec.ts` 锁定「不交叉」但没锁「检测⊇取件」）；导出循环内补 DB sha256 比对（不符即 `ARCHIVE_HANDOVER_FETCH_FAILED` 同口径拒绝）；引用件（笔迹图/照片/附件）纳入检测（按回流包引用反查）。

### 🔴 P1-2 存量开标文件包金额无单位（实测确认）

**实测**：演示项目 JJ-2026091003 的开标文件包（MinIO `bid-opening-handover/cmtveupp60016uu59lg543sme.json`）内 `openingRecords` 三家均为裸数字（152.9 / 153.95 / 153.8998），`amountUnit: null`；而 DB 中三家 `SupplierBidSubmission.envelopeVersion` 均为 `dual-v2`（万元口径）。

**根因三重叠加**：
1. 包初建于 2026-09-10（早于 09-14 单位铁律），当时代码无单位逻辑；
2. `completeOpening` 幂等短路（已生成直接返回既有产物），永不重算；
3. 开标签字重建 `rebuildHandoverWithSignatures`（`opening-sign.service.ts:241`）是**下载旧 JSON → 追加 signatures 段**，不重跑 `buildHandoverPackage`——09-21 的签字重建传播了 signatures 却没传播单位修复。

**影响**：违反「纸面证据金额一律自含单位」铁律（2026-09-14 定案）的存量面；离线读此卷者无法判单位（实际是万元）。且该机制决定存量包**不会自愈**——现行代码路径（单位戳优先/envelopeVersion 回退）是对的，但只对新开标项目生效。

**修复建议**：存量回填脚本（对 dual-v2 项目按 `buildHandoverPackage` 现行口径重建开标文件包、重算指纹；或最小化仅对 `openingRecords[].amount` 补 `amountUnit` 后重算 fingerprint）；同 key 覆盖 + FileAsset upsert 刷新指纹，与 N3/P1-17 同款。

### 🟡 P2-1 范围勾稽表（35 项）不含回流包等类目
