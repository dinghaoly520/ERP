# 3004 采购管理端工作台与三中心重设计方案

日期：2026-06-13

## 1. 背景与目标

3004 采购管理端重新定位为“采购管理工作台”。本轮不再保留原管理端中采购项目、开评标管理、评价管理、电子商城等页面与入口，而是聚焦三大核心能力：信息发布、供应商管理、专家管理。

目标是完成产品级重构：

- 首页从通用项目看板调整为采购管理驾驶舱。
- 信息发布、供应商管理、专家管理分别升级为中心页。
- 左侧导航只保留本轮核心业务入口。
- 前端彻底删除不属于本轮范围的页面与路由。
- UI 采用浅色政企科技风，兼顾正式可信与现代 SaaS 操作效率。

- 相关未使用 icon、类型、常量和前端 API 包装。

说明：本轮删除的是 3004 管理端前端页面。后端 API 与其他门户暂不删除，除非后续确认没有其他端依赖。

## 3. 信息架构与导航

最终信息架构：

```text
采购管理端
├─ /dashboard 首页驾驶舱
├─ /notice 信息发布中心
├─ /supplier 供应商管理中心
├─ /supplier/[id] 供应商详情
├─ /expert 专家管理中心
└─ /expert/[id] 专家详情
```

左侧导航：

```text
首页驾驶舱

核心业务
- 信息发布中心
- 供应商管理中心
- 专家管理中心

系统辅助
- 通知消息
- 个人信息 / 退出
```

导航原则：

- 左侧只放中心级入口，避免把子功能堆满侧边栏。
- 每个中心页内部承载子功能、流程卡片、统计卡、筛选和列表。
- 首页负责待办分流和全局总览。

## 4. UI 风格

采用“浅色政企科技感”：

- 主背景：浅蓝白渐变或极浅科技纹理。
- 主色：政企深蓝 `#064ea2`，科技蓝 `#0b63ce`。
- 卡片：白色卡片、细线边框、柔和阴影。
- 状态色：绿色表示完成/入库，橙色表示待处理，红色表示风险，紫色表示专家相关。
- 整体不做暗色大屏，保持浅色管理驾驶舱风格。
- 信息密度适中，使用现代 SaaS 式卡片、Tabs、表格和快捷操作。

## 5. 首页驾驶舱设计

首页定位为“采购管理驾驶舱 + 待办工作台”。

页面结构：

```text
首页驾驶舱
├─ 顶部欢迎区
├─ 关键指标
│  ├─ 今日待办
│  ├─ 待发布/待审核信息
│  ├─ 待审供应商
│  ├─ 专家待处理事项
│  └─ 风险预警
├─ 待办工作台
│  ├─ 信息发布待办
│  ├─ 供应商审核/变更待办
│  └─ 专家管理待办
├─ 风险与预警
│  ├─ 黑名单/异常供应商
│  ├─ 公告发布异常
│  ├─ 专家回避/履职异常
│  └─ 长时间未处理事项
├─ 三大中心入口
│  ├─ 信息发布中心
│  ├─ 供应商管理中心
│  └─ 专家管理中心
└─ 最近动态
   ├─ 发布动态
   ├─ 供应商动态
   └─ 专家动态
```

待办项统一结构：

```text
[类型标签] 标题
关联对象 / 提交人 / 时间
状态 / 优先级
操作按钮：查看、处理、稍后
```

首页成功标准：

- 登录后 5 秒内知道今天要处理什么。
- 所有指标只围绕信息发布、供应商、专家三大模块。
- 待办可一键进入对应中心页或详情页。
- 首页不再出现采购项目、开评标、评价管理、电子商城入口。

│  ├─ 编辑草稿
│  ├─ 定时发布

│  └─ 复制再发布

## 9. 数据与 API

本轮采用“前端先产品化重构，后端按缺口补聚合接口”的方式。

首页短期可以组合现有接口：

```text
GET /api/supplier/stats
GET /api/announcements/stats
GET /api/expert-admin
```

中期建议新增工作台聚合接口：

```text
GET /api/admin-workbench/summary
GET /api/admin-workbench/todos
GET /api/admin-workbench/alerts
GET /api/admin-workbench/activities
```

三大中心页：

| 模块 | 优先复用 | 可能补充 |
| --- | --- | --- |
| 信息发布中心 | `/api/announcements/*` | 发布待办、草稿统计、发布记录聚合 |
| 供应商管理中心 | `/api/supplier/*` | 变更待办、评价聚合、风险摘要 |
| 专家管理中心 | 现有专家管理接口 | 专家统计、回避关系、履职评价聚合 |

## 10. 权限

3004 管理端主要服务：

- `admin`
- `bid_host`
- `procurement_staff`

建议权限策略：

| 角色 | 首页 | 信息发布 | 供应商管理 | 专家管理 |
| --- | --- | --- | --- | --- |
| admin | 全部 | 全部 | 全部 | 全部 |
| procurement_staff | 全部 | 新建/编辑/发布 | 查看/审核/评价 | 查看/分配建议 |
| bid_host | 全部 | 查看/发布相关公告 | 查看供应商 | 查看/分配/履职跟踪 |

前端隐藏无权限按钮，后端写操作和聚合接口必须使用角色约束，不能只依赖前端隐藏。

## 11. 错误与空状态

三大中心页统一处理：

- 加载中：骨架屏或加载卡片。
- 无数据：模块化空状态文案和操作入口。
- 接口失败：顶部提示和局部重试按钮。
- 无权限：隐藏操作按钮，必要时显示“无权限操作”。
- 高风险操作：二次确认和原因填写。
