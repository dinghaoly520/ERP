# 电子商城管理完整闭环设计

日期：2026-06-14

## 背景

采购管理平台需要新增「电子商城管理」板块，用于采购中心维护 3002 电子商城展示的集中采购目录与价格。现有系统已经有 `CatalogItem`、`PriceHistory`、`AuditLog` 以及商城端 `/api/catalog` 数据读取能力，因此本设计采用扩展现有 Catalog 模块的方式实现后台管理、价格录入、目录管理和商城同步。

## 已确认范围

本轮实现完整闭环：

- 在 3004 采购管理平台新增「电子商城管理」导航分组。
- 新增四个子页：价格审批、价格录入、集中采购目录管理、同步与操作日志。
- 扩展后端 Catalog API，支持管理端新增、编辑、上下架、导入、模板下载、统计和日志查询。
- 价格录入支持手动填写和 CSV/Excel 文件导入。
- 文件导入按目录编码 `code` upsert：存在则更新，不存在则新增。
- 每次新增目录或价格变化写入价格历史。
- 后台操作写入审计日志。
- 3002 商城端读取同一套后端目录数据，只展示有效/可采购目录。

本轮不实现：

- 供应商端申请入口。
- 真实供应商价格申请/新增名录申请流程。
- 真实价格审批流。
- 独立异步同步任务。
- 物理删除目录。

「价格审批」本轮为管理型占位页，展示正式模块结构和未来流程说明。

## 推荐架构

采用「复用并扩展现有 Catalog 模块」方案。

### 现有能力

- `CatalogItem`：集中采购目录主数据。
- `PriceHistory`：目录价格历史。
- `AuditLog`：操作审计。
- `/api/catalog`：商城端目录读取接口。
- `apps/mall`：3002 商城端已从 `/api/catalog` 读取目录和价格历史。

### 新增能力

- 管理端 Catalog API：新增、编辑、状态变更、导入、模板下载、统计、日志过滤。
- 3004 采购管理平台电子商城管理页面。
- 商城端有效目录过滤。

不新增独立 `MallProduct` 表，避免目录与商城商品双源造成同步一致性问题。后续若要开放供应商申请，再新增 `CatalogPriceApplication` 一类申请表。

## 页面设计

### 导航

在 3004 采购管理平台左侧导航新增：

- 电子商城管理
  - 价格审批
  - 价格录入
  - 集中采购目录管理
  - 同步与操作日志

### 价格审批

本轮为管理型占位页。

页面内容：

- 统计卡片：待审批申请、本月通过、本月驳回、平均处理时长。
- 筛选区：申请类型、状态、关键词。
- 空表格状态：提示供应商端申请入口尚未开放。
- 未来流程说明：供应商提交 → 采购中心初审 → 价格生效 → 商城同步。
- 操作按钮禁用或提示“功能建设中”。

### 价格录入

用于采购中心工作人员新增目录和维护价格。

功能：

- 手动新增目录。
- 手动更新已有目录价格。
- 下载导入模板。
- 批量导入 CSV/Excel。
- 展示导入结果和错误行详情。

手动录入字段：

- 目录编码 `code`
- 名称 `name`
- 规格型号 `specification`
- 分类 `category`
- 分组 `group`
- 单位 `unit`
- 参考价 `referencePrice`
- 价格下限 `priceMin`
- 价格上限 `priceMax`
- 最近成交价 `lastDealPrice`
- 历史均价 `averagePrice`
- 供应商 `supplier`
- 供应商类型 `supplierType`
- 价格来源 `priceSource`
- 区域 `region`
- 是否含税 `taxIncluded`
- 是否含运费 `freightIncluded`
- 最小起订量 `minOrder`
- 有效期 `validUntil`
- 备注 `remark`

导入规则：

- 支持 `.xlsx`、`.xls`、`.csv`。
- 文件大小上限建议 5MB。
- 以 `code` 为业务唯一标识。
- `code` 存在则更新目录信息和当前价格。
- `code` 不存在则新增目录。
- 新增目录创建首条价格历史。
- 更新目录时，只有 `referencePrice` 变化才追加价格历史。
- 非价格字段变化不追加价格历史，但写审计日志。

导入结果：

- 总行数
- 新增数
- 更新数
- 失败数
- 失败行号
- 失败行目录编码
- 错误原因

导入采用逐行处理、汇总反馈。合法行正常新增/更新，非法行跳过并返回错误详情。

### 集中采购目录管理

用于维护现有商城目录。

页面内容：

- 统计卡片：目录总数、有效目录、下架/停用、价格预警/待复核、本月更新。
- 筛选区：分类、区域、状态、价格来源、关键词。
- 表格字段：目录编码、名称、规格、分类、单位、参考价、供应商、状态、更新时间。
- 行操作：查看详情、编辑、查看价格历史、下架/停用、启用。

删减规则：

- 不做物理删除。
- 使用下架/停用状态。
- 下架操作需要二次确认。
- 下架后后台仍可查询。
- 下架后 3002 商城默认不展示。
- 历史价格和审计日志保留。

### 同步与操作日志

用于查看电子商城管理相关操作。

页面内容：

- 筛选区：操作类型、操作人、时间范围、关键词。
- 表格字段：时间、操作人、操作类型、操作对象、影响数量、结果、详情摘要。
- 详情展开：展示 `AuditLog.detail` 中的导入统计、错误行、字段变更摘要、状态变更原因等。

同步说明：

- 3002 商城与后台读取同一套后端目录数据。
- 不需要独立同步任务。
- 后台更新后，商城刷新即可读取最新有效目录。
- 日志页展示的是后台操作和可见性变更记录，不是异步任务队列。

## 数据模型设计

### CatalogItem

继续作为集中采购目录主表。

要求：

- `code` 作为导入和更新的业务唯一键。
- 建议在数据库层确保 `code` 唯一；若当前 schema 尚未约束，应新增唯一索引或先处理重复数据后添加约束。
- 默认可采购状态为 `有效`。
- 商城端只展示 `status = '有效'` 的目录。

### PriceHistory

用于记录价格变化。

写入规则：

- 新增目录：创建首条价格历史。
- 手动改价：`referencePrice` 变化时追加。
- 导入更新：`referencePrice` 变化时追加。
- 非价格字段变化：不追加。

备注建议：

- `手动新增`
- `手动调价`
- `批量导入新增`
- `批量导入更新`

### AuditLog

用于电子商城管理操作追溯。

建议 action：

- `CATALOG_CREATED`
- `CATALOG_UPDATED`
- `CATALOG_PRICE_CHANGED`
- `CATALOG_STATUS_CHANGED`
- `CATALOG_IMPORTED`
- `CATALOG_TEMPLATE_DOWNLOADED`
- `CATALOG_EXPORTED`

`detail` 内容：

- 操作前后关键字段变化。
- 导入结果统计。
- 错误行摘要。
- 状态变更原因。
- 导出或查询筛选条件。
- 文件名等上下文。

### 申请表

本轮不新增供应商申请表。

原因：供应商端申请入口不在本轮范围内，价格审批也只是管理型占位。后续如要上线供应商价格申请，再新增申请表和审批流，避免现在产生无来源、无闭环的数据结构。

## API 设计

### 现有接口保留

- `GET /api/catalog`
- `GET /api/catalog/:id`
- `GET /api/catalog/:id/history`
- `GET /api/catalog/export`

`GET /api/catalog` 行为调整：

- 商城端默认只返回 `status = '有效'`。
- 管理端可通过参数查询全部状态。

### 新增管理接口

建议放在现有 Catalog 模块下：

- `GET /api/catalog/admin/stats`
  - 返回目录总数、有效数、下架数、待复核数、本月更新数等。

- `POST /api/catalog/admin/items`
  - 手动新增目录。
  - 写入首条价格历史和审计日志。

- `PATCH /api/catalog/admin/items/:id`
  - 编辑目录。
  - 价格变化时追加价格历史。
  - 写入审计日志。

- `PATCH /api/catalog/admin/items/:id/status`
  - 启用、下架、停用。
  - 不物理删除。
  - 写入审计日志。

- `GET /api/catalog/admin/import-template`
  - 下载导入模板。

- `POST /api/catalog/admin/import`
  - 上传 CSV/Excel。
  - 按 `code` upsert。
  - 返回新增、更新、失败统计和错误行详情。
  - 写入价格历史和审计日志。

- `GET /api/catalog/admin/audit-logs`
  - 返回电子商城管理相关日志。
  - 可复用现有 `/api/audit` 能力；如果现有接口不方便过滤，则新增专用包装接口。

## 权限设计

管理接口允许：

- `admin`
- `procurement_staff`

本轮至少保证种子账号 `caigou / caigou@2026` 可在 3004 使用电子商城管理。

商城读取接口继续允许商城账号读取，但默认只返回有效目录。

## 校验与错误处理

### 必填字段

- `code`
- `name`
- `specification`
- `category`
- `group`
- `unit`
- `referencePrice`
- `supplier`
- `priceSource`
- `region`

### 数字字段

- `referencePrice`
- `priceMin`
- `priceMax`
- `lastDealPrice`
- `averagePrice`
- `changeRate`

规则：

- 数字字段必须能解析为数字。
- 价格不能为负数。
- 如果同时填写 `priceMin` 和 `priceMax`，则 `priceMin <= referencePrice <= priceMax`。
- `validUntil` 如果填写，必须是有效日期。
- 布尔字段导入时支持 `是/否`、`true/false`、`1/0`。

### 导入错误处理

- 逐行处理，合法行提交，非法行跳过。
- 返回每个错误行的行号、目录编码和错误原因。
- 全部失败时不刷新列表，提示失败原因。
- 部分成功时刷新列表，提示“部分成功”。
- 后端负责最终校验，不能只依赖前端。

## 3002 商城同步规则

- 商城端继续调用 Catalog API。
- 商城列表只展示 `status = '有效'` 的目录。
- 后台新增有效目录后，商城刷新可见。
- 后台改价后，商城刷新展示新价格。
- 后台下架后，商城刷新不再展示该目录。
- 商城详情继续展示价格历史走势图。

## 测试设计

### API 单元测试

重点覆盖：

- 创建目录成功，并写入价格历史和审计日志。
- 更新目录价格时追加价格历史。
- 更新非价格字段时不追加价格历史。
- 下架目录后商城列表不返回。
- 导入新编码时新增目录。
- 导入旧编码时更新目录。
- 导入错误行时跳过并返回错误详情。
- 导入部分成功时统计正确。
- 管理接口权限校验。

### 前端手动验证

重点覆盖：

- `caigou / caigou@2026` 登录 3004 后能看到电子商城管理。
- 价格审批占位页展示正常。
- 手动新增有效目录后，目录管理可见，3002 商城可见。
- 手动改价后，商城刷新显示新价格，详情价格历史新增记录。
- 下架目录后，后台仍可见，3002 商城不可见。
- 批量导入后，新增、更新和错误行反馈正确。
- 同步与操作日志能看到导入、改价、下架等记录。

## 实施顺序建议

1. 后端确认 `CatalogItem.code` 唯一约束和状态过滤规则。
2. 扩展 Catalog DTO、Service、Controller 管理端接口。
3. 实现导入模板和 CSV/Excel 解析。
4. 补充价格历史和审计日志写入。
5. 增加 API 单元测试。
6. 在 3004 增加电子商城管理导航和四个页面。
7. 调整 3002 商城端目录过滤，确保只展示有效目录。
8. 做完整手动验证。

## 验收标准

- 采购管理平台出现电子商城管理分组和四个子页。
- 价格审批为管理型占位页，不出现真实审批误导。
- 价格录入支持手动新增和 CSV/Excel 导入。
- 导入按 `code` 更新已有目录或新增目录，并返回错误行详情。
- 集中采购目录管理支持编辑、查看历史、下架/启用。
- 下架目录不在 3002 商城展示。
- 有效目录新增或改价后，3002 商城刷新可见最新数据。
- 价格变化写入 `PriceHistory`。
- 后台操作写入 `AuditLog` 并能在日志页查看。
- API 测试和前端手动验证通过。
