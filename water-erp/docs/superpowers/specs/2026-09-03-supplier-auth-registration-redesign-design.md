# 供应商登录与双注册流程重设计

日期：2026-09-03  
状态：视觉方向与流程方案已确认

## 1. 背景

当前 `3004` 实际运行的是 `apps/supplier-portal-next`，不是专家门户。现有供应商登录和注册页面已经形成明确的视觉资产：水利工程实景、水宝吉祥物、蓝青品牌色、浅色新拟态表面和偏正式的中文排版。本次不替换这套风格，只修正信息层级、注册入口表达和正式注册、临时注册之间的流程一致性。

用户已确认：

- 登录页采用视觉方案 B：保留现有登录主体，把正式注册和临时注册重排为两个并列且带说明的入口。
- 注册采用流程方案 A：两类注册使用共同骨架，临时注册按业务需要合理缩短。

## 2. 目标

1. 保留原页面辨识度，提升登录区的主次关系、文字节奏、对齐和可读性。
2. 让用户在登录页直接理解正式注册与临时注册的适用场景。
3. 让两类注册共享相同的页面骨架、阶段命名、字段顺序、反馈方式和确认方式。
4. 在临时注册中增加业务标签，并贯通前端类型、接口 DTO、持久化和自定义标签待审核逻辑。
5. 按仓库实际运行情况修正文档中的门户目录及端口映射。

## 3. 非目标

- 不改变供应商登录、正式注册和临时注册的公开路由。
- 不重做认证机制、邀请码规则、短信能力或供应商审核制度。
- 不引入新的 UI 组件库、动画库或字体依赖。
- 不重构与本次页面无关的供应商门户功能。
- 不改变正式注册现有字段的业务含义。

## 4. 设计语言

Design Read：面向外部供应商的登录与准入流程重设计，保留现有水利实景、吉祥物与浅色新拟态质感，采用可信、精确、克制的工业水利视觉语言。

- `DESIGN_VARIANCE: 4`
- `MOTION_INTENSITY: 3`
- `VISUAL_DENSITY: 5`

视觉规则：

- 保留背景实景、水宝、Logo 和现有蓝青色资产。
- 整页只使用品牌蓝作为交互强调色，模块不再分别使用蓝、绿、橙、红等装饰色。
- 新拟态仅用于页面主表面、输入框和主要按钮，避免每个区块都形成厚重悬浮卡片。
- 使用细边线、精确对齐和小范围阴影建立层级；圆角沿用现有体系并减少不必要的胶囊形态。
- 图标继续使用项目既有的 Lucide，统一描边粗细，不保留手写 SVG 图标。
- 页面高度使用动态视口单位，进入动画克制，并支持 `prefers-reduced-motion`。

## 5. 页面与信息架构

### 5.1 登录页 `/login`

登录仍然是页面唯一主任务：

1. 品牌标识与“供应商门户”形成单一清晰标题组，减少重复品牌信息造成的竞争。
2. 用户名、密码和登录按钮保持现有顺序与接口行为。
3. 审核进度查询和忘记密码作为辅助操作，视觉权重低于登录。
4. “首次使用平台？”之后展示两个等宽注册入口：
   - 正式注册：长期合作，完成完整资料入库。
   - 临时注册：已获邀请，凭 8 位邀请码办理。
5. 两个入口具有明确标题、简短说明和方向图标，但不与登录主按钮竞争。

### 5.2 正式注册 `/register`

正式注册由现有六部分整理为五步：

1. 身份与账号：手机号验证、登录密码。
2. 企业与业务：企业主体信息、法定登记信息、业务标签。
3. 联系人：法定代表人和业务联系人。
4. 资质与履历：银行账户、资质证照、主体业绩。
5. 确认提交：统一总览、协议确认、审核说明。

此调整只合并逻辑相关内容，不删除业务字段。

### 5.3 临时注册 `/register-temporary`

临时注册从单一长页面调整为四步：

1. 邀请与账号：8 位邀请码、登录密码。
2. 企业与业务：企业主体信息、法定登记信息、业务标签。
3. 联系人：法定代表人和业务联系人。
4. 确认提交：统一总览、协议确认、临时资格说明。

临时注册不显示正式注册独有的资质与履历步骤。省略来自业务要求，而不是另建一套页面逻辑。

## 6. 共享组件边界

本次提取少量、职责明确的共享组件，不建立通用动态表单引擎：

- `RegistrationShell`：背景、品牌头部、步骤导航、内容区域、返回登录和移动端布局。
- `RegistrationStepper`：当前步骤、已完成状态、可回退规则和紧凑移动端表现。
- `RegistrationSection`：区块标题、说明、图标和一致的字段网格。
- `BusinessTagField`：推荐标签、自定义标签、2 至 8 项限制、去重和错误显示。
- `PasswordField`：密码显示切换、统一 Lucide 图标、可访问名称和错误区域。

正式与临时注册页面各自保留表单状态、步骤校验和提交请求，避免为了复用而把不同业务规则塞入一个复杂配置对象。

## 7. 业务标签数据流

### 7.1 前端

- `RegisterTemporaryParams` 增加 `tags: string[]`。
- 临时注册复用正式注册的标签来源和交互组件。
- 用户必须选择 2 至 8 个标签。
- 自定义标签提交前执行去首尾空格、空值过滤和精确去重；单项最长 20 个字符。
- 确认页显示最终标签列表，返回上一步后保留选择。

### 7.2 API

- 临时注册 DTO 增加必填 `tags` 字段。
- 服务端验证数组长度为 2 至 8，且每项为最长 20 个字符的非空字符串。
- 服务层再次规范化和去重，防止绕过前端校验。
- 临时供应商记录保存最终标签列表。
- 不在标签目录中的自定义值沿用正式注册逻辑，创建待审核的 `BusinessTag` 记录并触发现有通知路径。
- 标签保存与临时供应商创建处于同一事务边界，避免只创建供应商但丢失标签审核记录。

## 8. 校验、错误和状态

- 每一步只校验当前步骤字段；通过后才能进入下一步。
- 错误显示在对应字段下方，同时聚焦或滚动到首个错误字段。
- 步骤导航允许返回已完成步骤，不允许直接跳过未完成步骤。
- 接口错误显示在提交区域的可访问状态容器中，不清空用户已填写数据。
- 邀请码无效、重复企业、短信失败和网络失败保留后端原始业务语义，并使用统一视觉格式。
- 提交期间禁用重复提交；成功后沿用现有结果页或登录跳转行为。
- 登录页查询状态文案使用正常中文标点，不使用视觉上突兀的长横线分隔。

## 9. 响应式与可访问性

- 登录页桌面端保留左侧场景和右侧登录卡；移动端将卡片置于主要可视区域，并保证注册入口可触达。
- 注册页桌面端使用居中的宽表单表面，字段按语义组成一列或两列；小于 `768px` 时全部切换为单列。
- 移动端步骤导航显示当前步骤名称、序号和整体进度，避免横向挤压完整五步标签。
- 所有字段使用可见标签，不使用占位符代替标签。
- 输入框、按钮和标签选择项的触摸目标不小于 44 像素。
- 焦点样式、提示文字、错误文字和禁用状态满足 WCAG AA 对比度。
- 密码显示按钮、业务标签和步骤导航提供明确的键盘与屏幕阅读器语义。

## 10. 验证策略

### 10.1 API 自动化验证

- DTO 测试：缺少标签、少于 2 项、多于 8 项、超长标签和合法标签。
- 服务测试：临时注册保存标签、标签去重、自定义标签创建待审核记录、事务失败不产生部分数据。
- 既有正式注册行为保持通过。

### 10.2 前端验证

- 运行供应商门户 ESLint 和生产构建。
- 验证正式注册五步和临时注册四步可前进、回退并保留数据。
- 验证两类注册的业务标签具有相同选择、添加、删除、限制和错误反馈。
- 验证登录、正式注册和临时注册在桌面与窄屏下无溢出、遮挡或不可达操作。
- 验证密码显示切换、键盘焦点、加载状态、错误状态和减少动画偏好。

### 10.3 浏览器回归路径

1. `/login` 登录主流程和两个注册入口。
2. `/register` 从第一步到确认提交的完整路径。
3. `/register-temporary` 从邀请码到确认提交的完整路径。
4. 临时注册提交后，通过接口或数据库结果确认标签已持久化，自定义标签进入待审核状态。

## 12. 验收标准

- 页面一眼仍能识别为现有“智慧水发 · 蜀水云采”供应商门户，而不是全新模板。
- 登录是视觉主任务，正式和临时注册的区别无需进入下一页即可理解。
- 正式注册为五步，临时注册为四步，共享相同的视觉、阶段语义和操作反馈。
- 临时注册可填写 2 至 8 个业务标签，并从 UI 一直保存到数据库。
- 自定义标签在两类注册中使用相同待审核逻辑。
- 现有路由、正式注册字段、登录接口和成功跳转不发生回归。
- 目标应用 lint、生产构建和相关 API 测试通过，四条浏览器回归路径通过。
- 根目录文档不再把 `3004` 描述为专家门户。
