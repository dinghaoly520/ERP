# 3004 供应商门户全量整改设计

日期：2026-09-03  
状态：已由用户依据 2026-09-03 审计结论批准实施

## 1. 背景

`apps/supplier-portal-next` 是当前运行于 3004 的供应商门户。现有系统已覆盖供应商准入、资料维护、项目发现、资格预审、投标、开标、澄清、异议、合同、框架协议、目录供货、消息和归档等主要页面，但审计发现若干安全、业务断链、交互一致性、无障碍和工程质量问题。

本次整改保留现有“智慧水发 · 蜀水云采”工业水利设计语言，不做无关的全站换肤。衡量标准从“页面是否存在”提升为“供应商动作能否被采购端、开评标端、专家端、商城端和统一 API 正确承接并留下可验证凭证”。

## 2. 目标

1. 修复合同履约证明跨合同越权风险，并校验上传资产归属。
2. 打通成交通知书从消息、导航、文件查看下载到签收回执的完整路径。
3. 补齐供应商忘记密码申请、资格预审申请和合同满意度评价的正式表单。
4. 统一所有时限判断到服务器标准时钟。
5. 把首页升级为可执行的供应商待办工作台，并提供项目完成历史入口。
6. 统一消息类型、内部链接、安全展示和行动入口。
7. 修复通用组件和关键列表的语义、键盘、焦点、触控与移动端适配。
8. 收敛本次涉及页面的颜色、间距、阴影、字体和响应式实现，优化登录首屏资源。
9. 恢复供应商门户 ESLint 质量门禁，并减少跨端契约中的无类型数据。
10. 保持现有投标、U 盾、双信封、开标、临时供应商和注册改造不回归。

## 3. 非目标

- 不改变采购制度、供应商审核制度或中标决策规则。
- 不在本轮重构整个 14,000 行全局样式文件；只建立明确的新单源区并迁移本次触达组件，剩余历史层作为后续机械治理项。
- 不凭空建设短信、邮件、银行或 CA 外部服务；只为已有站内能力和接口预留一致边界。
- 不把 GB/T 43711—2024 对平台整体的全部要求都解释为 3004 单端职责；PDF 差距将在整改后单独形成矩阵。
- 不覆盖工作区中用户现有的未提交修改。

## 3.1 方案选择

评估过三种实施方式：

1. **闭环优先的渐进整改（采用）**：先修安全与断链，再把表单、消息、通用组件和响应式能力收敛到共享边界。优点是风险可测试、能保留现有业务资产，也适合当前有大量在途修改的工作区。
2. **供应商门户整体重写**：可以一次性清理样式和类型债，但会扩大回归面，并可能覆盖刚完成的注册、归档、公告和投标改造，不适合当前基线。
3. **只修 API 和错误链接**：上线最快，但会保留不可发现入口、原生 `prompt()`、焦点缺陷和跨端状态漂移，不能满足用户提出的“全部修复”。

因此本设计采用方案 1，并以独立测试和逐页面回归控制改动风险。

## 4. 工作树保护策略

当前工作区已包含注册、合同、公告、异议、归档、API 和共享包的用户在途修改。它们是本次实施基线。

- 在 `codex/supplier-portal-hardening` 分支上工作。
- 只使用聚焦补丁修改目标区域。
- 每次改动前后检查目标文件 diff，不重置、不恢复、不批量暂存其他文件。
- 由于目标文件混有用户既有修改，本次不自动提交这些混合文件；最终提供精确 diff 和验证结果。

## 5. 安全与接口边界

### 5.1 合同履约证明

- API 必须以当前供应商、合同 ID、履约节点 ID 三者共同确认所有权。
- `proofAssetId` 必须存在，属于当前登录用户或其供应商主体，并属于允许的履约证明业务类别。
- 越权、资产不存在、资产不属于当前主体分别返回稳定错误码。
- 成功挂接写入审计记录，包含合同、履约节点、资产和操作人。

### 5.2 成交通知书

- 通知内部链接统一为真实路由 `/award-letters`。
- 列表 API 返回可安全展示的通知书资产元数据和签收状态。
- 供应商只能查看、下载、标记已收和签收本企业的通知书。
- 页面必须先提供文件查看/下载，再提供签收；签收后展示服务器时间、签收人和回执标识。
- `receivedAt` 仅在明确打开文件或用户确认查看时更新，不由不可访问的卡片点击暗中触发。

### 5.3 密码重置

- 登录页拆分“查询审核进度”和“忘记密码”两个入口。
- 忘记密码表单提交用户名、申请人姓名和联系方式到既有匿名接口。
- 表单具备字段校验、提交中状态、限流/业务错误说明和成功后的处理指引。
- 不泄露用户名是否存在之外的敏感账户信息。

## 6. 业务流程与页面设计

### 6.1 工作台

首页新增基于现有数据聚合的“当前待办”，至少覆盖：资料补正、临近截止项目、投标草稿、开标提醒、未读澄清、待签收通知书、合同履约证明和资质到期提醒。每项包含状态、截止时间、来源项目和唯一行动入口。

首页项目紧急度、通知新旧判断和所有倒计时统一使用 `@water-erp/shared` 的服务器时钟偏移。没有数据时展示完成态，不制造虚假待办。

### 6.2 导航与项目历史

- 左侧菜单加入“成交通知书”和“合作历史”，避免只能从一次性通知进入。
- 保持正式与临时供应商能力差异；临时供应商仅看到其有权限的项目和通知入口。
- “已完成项目”复用已有页面，归入投标进展或中标与合同信息架构。

### 6.3 资格预审

- 用受控对话框替代 `prompt()`。
- 补充说明确实为选填；空白可提交。
- 弹窗展示预审名称、有效期、申请要求和提交影响，并返回明确成功回执。

### 6.4 合同履约与满意度

- 使用可见文件选择控件或正式弹窗，显示格式、大小、选中文件、上传进度、失败原因和重试。
- 满意度使用 1 至 5 分表单，意见为选填；已有评价时展示并允许按后端规则更新。
- 框架协议中的结构化数量/占比规则转换为中文业务描述，不直接显示 JSON。

### 6.5 消息中心

- 建立共享消息元数据表，覆盖 API 实际产生的类型，包括 `AWARD_LETTER`、`BID_ROUND_OPEN`、`BID_NUDGE_SUPPLIER`、`BID_SCHEDULE_CHANGE` 和密码审批结果。
- 一级分类收敛为待办、项目动态、审批、合同、系统；详细类型作为二级筛选。
- 内部链接只存储和路由站内路径；完整 URL 经同源校验后转换，外部 URL 明确标识并新窗口打开。
- 列表展示摘要，不直接暴露环境域名或冗长原始正文。

## 7. 通用交互与无障碍

- `SpPageHero` 输出唯一页面 `h1`。
- 可点击 KPI、公告、项目、消息和历史项目使用原生链接/按钮，或完整实现 `tabIndex`、Enter/Space 键盘语义。
- `SpDialog` 使用 `aria-labelledby`，打开后聚焦合适控件，Tab 焦点保持在弹窗内，Escape 关闭，关闭后恢复触发点。
- Tabs 使用 `tablist/tab/aria-selected` 和方向键；分页按钮有可访问名称；进度条具有 `progressbar` 值语义；加载和结果状态使用实时区域。
- 移动抽屉具有名称、`dialog` 语义、焦点管理、Escape 关闭和背景滚动锁定。
- 所有关键触控目标不小于 44×44px；可见焦点满足 WCAG AA。

## 8. 响应式与视觉收敛

- 桌面保留高信息密度侧栏工作台；平板使用抽屉和两列内容；手机使用单列、摘要卡片和可展开详情。
- 关键能力不得在手机上隐藏。宽表在窄屏转为带字段标签的卡片，而不是只依赖横向滚动。
- 新拟态仅用于主表面和关键动作，列表与正文用细线、底色和排版层级，减少卡片套卡片。
- 新增/修改样式只使用现有 OKLCH 令牌或补充的语义令牌，不增加页面级硬编码颜色。
- 登录背景提供 WebP/AVIF 或等价的现代压缩资源与 PNG 回退，根据分辨率选择合适尺寸。
- 中文正文优先使用稳定系统中文字体栈；移除本次页面不需要的重复拉丁字体请求。

## 9. 类型、质量与性能

- 添加可执行的 ESLint 9 flat config 和供应商门户所需依赖，使 `pnpm --filter supplier-portal-next lint` 成为有效门禁。
- 为本次触达的通知、工作台、合同、成交通知书、资格预审 API 建立显式类型，不新增 `any`，并消除这些数据边界上的现有 `any`。
- 保持服务端分页；搜索请求防抖；轮询仅在页面可见和登录有效时进行，离开页面后清理。
- 使用构建产物和浏览器网络数据对比优化前后 CSS、图片和首屏请求。

## 10. 测试策略

### 10.1 API

- 合同属于当前供应商且履约节点属于合同、资产属于主体时成功。
- 合同越权、履约节点跨合同、资产越权和资产类别错误均拒绝。
- 成交通知书列表、接收、签收、文件访问均验证供应商所有权。
- 通知链接使用真实路由并包含完整成交通知字段。
- 密码重置沿用既有接口测试并补供应商端契约覆盖。

### 10.2 前端

- 为共享消息元数据、站内链接规范化、框架规则格式化、待办聚合和服务器时间计算编写单元测试。
- 为密码重置、资格预审、合同评价和通知书签收编写组件测试或可复用逻辑测试。
- 用静态测试锁定页面标题、ARIA、键盘和导航入口。

### 10.3 浏览器回归

验证 `/login`、`/dashboard`、`/bids`、`/my-bids`、`/prequal`、`/award-letters`、`/completed-projects`、`/contracts`、`/frameworks`、`/notifications`、`/announcements`、`/objections`，覆盖桌面与窄屏、键盘操作、加载/空/错误状态。

## 11. 验收标准

- 已知合同履约证明越权路径由自动化测试证明被阻断。
- 成交通知消息不再 404，供应商可查看/下载真实文件并获得签收凭证。
- 忘记密码、资格预审空说明和合同满意度均可通过正式表单完成。
- 首页和项目页对同一截止时间给出一致判断。
- 成交通知书与合作历史可从导航稳定进入。
- 关键流程可仅用键盘完成，弹窗和移动抽屉焦点行为正确。
- 390px、768px、1280px 三类视口无关键功能缺失或不可读表格。
- `lint`、相关 API 测试、供应商门户类型检查和生产构建均可执行并通过；若存在与本次无关的基线失败，需单独列出证据。
- PDF 规范对照矩阵明确区分：已落实、部分落实、未落实、平台其他端职责、需外部系统对接。
