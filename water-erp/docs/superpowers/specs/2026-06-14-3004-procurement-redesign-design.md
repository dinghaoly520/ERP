# 3004 采购管理系统浅色运营指挥台重设计

日期：2026-06-14

## 背景

3004 端是采购管理工作台，当前覆盖信息发布、供应商管理、专家管理等采购管理员日常工作。现有页面已经具备基础驾驶舱、侧栏导航和主要模块页面，但视觉上更接近普通后台，首页部分模块也偏待办聚合，未充分体现“运营总览”和数据驾驶舱价值。

本次重设计采用浅色系数据驾驶舱风格，在不改变现有核心路由和业务流程的前提下，提升左侧工具栏、首页驾驶舱和主要列表页的一致性、专业感与实用性。

## 目标

1. 将 3004 端整体视觉升级为“浅色运营指挥台”。
2. 保持现有四大导航入口，降低用户迁移成本。
3. 将首页驾驶舱从待办聚合页升级为采购运营总览页。
4. 统一公告、供应商、专家主要列表页的页面骨架与视觉语言。
5. 所有首页和列表页指标使用真实接口或现有页面数据，不引入 mock fallback。

## 非目标

本次不做以下内容：

- 后端接口结构调整。
- 新增虚假的趋势、同比、环比数据。
- 重排现有路由或重构业务流程。
- 深色大屏模式。
- 登录页重设计。
- bid-portal、expert-portal、supplier-portal、mall 的同步改造。

## 视觉方向

采用“浅色运营指挥台型”设计：

- **浅色数据感**：白色、浅蓝、冰蓝、浅青为主，避免深色大屏。
- **专业政企感**：保留水务集团蓝色主色，减少花哨效果。
- **实用优先**：卡片、指标和分区都必须服务于管理判断或下钻处理。
- **清晰层级**：通过边框、阴影、渐变背景、状态徽章和分区标题建立视觉层次。

颜色语义：

- 蓝色：主业务、总览、公告/信息发布。
- 青色：运行态势、实时/效率类信息。
- 绿色：已完成、已入库、正常状态。
- 橙色：待处理、待审核、滞留。
- 红色：风险、黑名单、异常。
- 紫色：专家资源、抽取、评价。

## 页面骨架

整体仍保持顶部品牌栏、左侧工具栏和主内容区：

```text
顶部栏
├─ 系统名 / 当前工作台标签
└─ 用户信息 / 退出

左侧工具栏 + 主内容区
├─ 首页驾驶舱
├─ 信息发布中心
├─ 供应商管理中心
└─ 专家管理中心
```

主内容区采用浅蓝渐变和细微光晕背景。内容卡片使用统一圆角、边框、浅阴影和状态色。

## 左侧工具栏设计

### 信息架构

保持现有四大入口：

```text
首页驾驶舱
信息发布中心
供应商管理中心
  - 供应商审批
  - 供应商库
  - 供应商选取
  - 供应商评价
专家管理中心
  - 专家录入
  - 专家库
  - 专家抽取
  - 专家评价
```

不新增复杂层级，不改变现有路由。

### 视觉结构

侧栏从深色普通菜单调整为浅色数据指挥台导航：

- 背景使用白色或极浅蓝渐变。
- 外边框使用浅蓝灰。
- 当前选中项使用蓝色渐变底和左侧高亮条。
- 未选中项使用深灰蓝文字，hover 时显示浅蓝底。
- 分组展开项使用浅色轨道线连接子菜单。
- 子菜单选中态使用浅蓝填充和蓝色文字。

### 可用性

- 保留折叠态，只显示图标。
- 当前路由所在父级分组自动展开。
- 父级和子级都显示 active 状态。
- 展开态下一级菜单可显示短副标题：
  - 信息发布中心：公告 / 公示 / 政策。
  - 供应商管理中心：审批 / 库 / 评价。
  - 专家管理中心：录入 / 抽取 / 履职。
- 底部保留折叠按钮，视觉上作为工具栏控制。

### 顶部栏

顶部栏改为更实用的工作台信息区：

- 左侧显示系统名和当前工作台标签。
- 右侧显示用户、角色和退出。
- 如果当前通知数据不稳定，不新增硬编码消息入口。

## 首页驾驶舱设计

首页定位为“采购运营总览驾驶舱”。用户进入后应在 10 秒内判断：

1. 公告/信息发布是否正常推进。
2. 供应商库规模与审核状态如何。
3. 专家资源与履职是否正常。
4. 当前是否存在明显风险或滞留事项。
5. 下一步应点击哪里处理。

### 首屏布局

```text
采购运营总览
├─ 今日/本期运行摘要 + 关键操作按钮
├─ 4-6 个关键 KPI
├─ 业务运行态势 / 分模块健康度
├─ 风险与效率摘要
└─ 信息发布 / 供应商 / 专家 三大业务概览
```

### 首屏 KPI

建议首屏展示 5 个关键指标：

1. **信息发布总量 / 已发布**
   - 说明公告发布工作体量与公开状态。
   - 点击进入信息发布中心。
2. **供应商总数 / 已入库**
   - 说明供应商资源规模。
   - 点击进入供应商库。
3. **专家总数 / 参与记录**
   - 说明专家资源与使用情况。
   - 点击进入专家管理。
4. **待处理事项**
   - 聚合待发布/待审核/专家未完成。
   - 点击进入待办明细区或对应模块。
5. **风险预警数**
   - 聚合停用/黑名单供应商、专家未完成提醒等。
   - 点击进入风险摘要区。

不展示无法由真实数据支撑的趋势、同比或环比。

### 中部模块

#### 业务健康度

展示 3 条业务健康度：

- 信息发布健康度：已发布 / 总数。
- 供应商库健康度：已入库 / 总数。
- 专家履职健康度：专家事项完成度，或以未完成数量进行反向提示。

#### 风险与效率摘要

展示以下管理提示：

- 停用/黑名单供应商数量。
- 待审供应商数量。
- 待发布/未发布公告数量。
- 专家未完成事项数量。
- 数据更新时间。

每条提示都提供明确入口，例如“查看供应商审批”“查看专家管理”。

#### 三大业务概览

信息发布、供应商、专家三个模块分别展示：

- 当前关键数量。
- 最近需要关注的状态。
- 进入该中心的主按钮。
- 简明业务说明。

### 底部模块

将“最近动态”改为管理摘要：

- 发布动态：已发布、未发布、公告类型分布。
- 供应商动态：总数、已入库、待审、风险状态。
- 专家动态：专家总数、参与记录、未完成事项。

如果接口不足，优先展示现有数据可计算字段。

## 主要列表页统一设计

主要列表页不重写业务逻辑，只统一视觉结构。

页面骨架：

```text
页面标题区
├─ 标题 / 副标题 / 当前业务说明
└─ 主要操作按钮

统计摘要区
└─ 2-4 个关键统计卡片

筛选/搜索区
├─ 搜索
├─ 状态筛选
└─ 其他已有筛选

内容区
├─ 表格 / 卡片 / 列表
├─ 状态徽章
└─ 操作按钮
```

统一要求：

- 保留页面已有接口和业务操作。
- 保留 loading 状态。
- 保留 empty state。
- 请求失败时显示清晰错误状态。
- 状态徽章使用统一颜色语义。
- 操作按钮大小、圆角、边框、hover 态保持一致。

## 数据流

### 首页数据

继续使用现有真实接口：

- `/api/auth/me`
- `/api/supplier/stats`
- `/api/announcements/stats`
- `/api/expert-admin`

可推导的信息包括：

- 公告总数、已发布、未发布/待发布。
- 供应商总数、待审、已入库、停用、黑名单。
- 专家数量、参与记录、未完成专家事项。
- 聚合待办与风险数量。
- 当前数据更新时间。

### 列表页数据

沿用各页面当前接口，不改 API 契约。展示层必须遵守：

- 接口失败不显示假数据。
- 加载中显示 loading。
- 空数据显示 empty state。
- 可计算的统计从当前真实列表或统计接口中得出。
