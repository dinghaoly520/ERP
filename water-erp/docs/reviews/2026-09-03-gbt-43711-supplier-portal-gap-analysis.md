# 3004 供应商门户与 GB/T 43711—2024（非招标方式）差距复核

日期：2026-09-03  
复核对象：当前工作树中的 3004 供应商门户、统一 API 及其采购/公告/商城/专家/开评标协同端  
参考文件：`电子采购交易规范 非招标方式.pdf`

## 1. 结论

本系统已形成“供应商注册入库 → 项目发现/邀请 → 采购文件获取 → 响应与撤回 → 开启/解密 → 澄清/异议 → 成交通知 → 合同与履约 → 归档”的主要线上骨架。本轮又补齐了注册附件上传、成交通知书附件与签收、线上成交供应商强绑定、合同签署证据、履约证明权限、通知深链、正式表单、服务器时钟、待办工作台、移动端及无障碍等关键缺陷。

但若以规范中的强制“应”条款作为平台级验收口径，当前仍不能判定为全面落实。最重要的缺口集中在：在线投诉、真正的电子竞价、隔离式多轮谈判、终止/采购方式转换后的供应商通知、响应文件服务端完整性、原始采购文件不可物理删除，以及合同电子订立。框架协议、资格预审、保证金、公共服务/监管/CA/金融外部对接仍属于部分落实。

这份结论区分两类内容：

- **规范落实项**：可直接对应 GB/T 43711—2024 的“应/宜/可”条款及附录流程。
- **产品质量增强**：密码重置、SM2 通知书签收、客户端服务器时钟、无障碍和移动体验很重要，但不能表述为该规范明确规定的功能。

## 2. 当前端口与职责边界

以 `packages/config/src/ports.ts` 为准，当前实际协同边界如下：

| 端口 | 系统 | 在供应商业务中的职责 |
|---|---|---|
| 3002 | 信息门户 | 匿名公告、采购/成交/履约信息公开、政策与处罚信息 |
| 3003 | 采购商城 | 商品选择、预算清单、目录与供应商供货关系 |
| 3004 | 供应商门户 | 注册、资料、响应、解密、澄清、异议、通知书、合同履约、框架/目录 |
| 3005 | 采购管理工作台 | 项目、文件、资格预审、评审结果、通知书、合同、供应商管理 |
| 3006 | 专家门户 | 独立评审、澄清发起、回避与报告 |
| 3007 | 开评标端 | 开启、解密协调、唱标确认、开评标记录与争议处理 |
| 4001 | 统一 API | 权限、状态机、对象存储授权、通知、审计和跨端契约 |
| 外部系统 | 公共服务、监管、CA、银行/保险 | 跨平台发布、监管推送与投诉、证书互认、保证/支付回执 |

因此，3004 页面存在并不等于流程闭环；关键动作必须同时在 4001 强制校验，并由 3005/3007 或外部系统承接。

## 5. 推荐实施顺序

### 第一批：合规与交易安全（P0）

1. 服务端强制响应文件、签章、保证金和项目规则，消除绕过 UI 的空响应提交。
2. 建立在线投诉及监管办理闭环。
3. 分拆“竞价”和“谈判”状态机：竞价提供真实多轮实时匿名排名；谈判提供供应商隔离会话与文件交换。
4. 终止/采购方式转换时通知全部参与供应商，并保留前后项目关系。
5. 已发布采购文件改为不可物理删除，仅允许版本化更正/作废，并启用对象锁。
6. 合同签署期限改为服务端硬闸，补供应商电子协商与双方签署。

### 第二批：端到端完整性（P1）

1. 资格预审材料、截止、有限数量评审和申请级通知书。
2. 取消成交、候补递补、补证及公示后的状态机。
3. 框架协议开放申请、供应商退出、协议文件、变更和第二阶段竞争。
4. 逐供应商保证金收退账与外部保函/支付回执。
5. 修复 3003 商城角色与预算/导出/转立项契约。
6. 公告外部发布、全过程监管推送与澄清附件下载授权闭环。

### 第三批：平台治理与外部能力（P2）

1. 自然人/非法人主体及 A/B/C 标准编码。
2. 表 B.1 统一数据公开与保密策略。
3. CA 互认、信用、银行保险、公共服务和监管正式联调。
4. 15 年留存、音视频、容灾、压测、等保和恢复演练证据。
5. 第三方评价和持续改进工单。
6. 匿名注册上传的未认领对象回收、单会话文件/字节配额，以及验证码消费与数据库事务之间的幂等预约。
7. 合同公告/新增履约节点面向成交供应商的定向站内消息生产者；如升级为待办，需同时定义完成动作与 `resolvedAt` 消解规则。
8. 用数据库唯一的业务资产绑定表替代跨表引用扫描，进一步强化高并发下通知书、签署件和履约证明的唯一占用。

## 6. 规范解释边界

- 规范要求数字证书支持身份验证、签章、加解密和互认，但未指定必须使用 SM2。
- 规范要求采购人及时发出成交通知书，并建议包含项目、采购人、成交内容、履行期限、签约事项及采购人签章日期；未要求供应商必须对通知书进行 SM2 签名回执。
- 规范未规定“忘记密码”功能，也未规定客户端时钟同步的具体实现。服务器权威判时、密码重置和无障碍能力属于必要的安全/质量增强。
- 合同履约证明的“合同—节点—文件—供应商”关系校验是正确的本地安全实现，但不是规范指定的算法。
- “宜/可”条款与外部对接项不应被误标为已完成；应以生产回执、联调报告和运行证据验收，而不是仅看页面或预留字段。
- 旧数据迁移会把“无履约记录、无签署件”的历史 `signed` 合同安全回退为“待签署”；已进入履约/验收却缺签署件的异常合同会阻断迁移并要求人工补证，避免静默改写历史。
