## 一、NTP 修复（两台机都做，零停机，先做）

```bash
# 10.60.14.14 与 10.10.7.20 各执行：
systemctl is-active chronyd
chronyc sources -v          # 看有无 ^*（已锁定源）；全部 ^? = 源不可达，按下面选
```

**首选：公司内网时间服务器 10.10.205.99**（两台机同配；公网授权/手动校准兜底均不再需要）：

```bash
# /etc/chrony.conf：注释公网死源行，加：
server 10.10.205.99 iburst
# 前端机可选后备：server 10.60.14.14 iburst
systemctl restart chronyd && sleep 30
chronyc sources -v | tail -4     # 期望 ^* 10.10.205.99；一直 ^?=跨网段 UDP123 被拦找网络组放行内网；
                                 # stratum 0/16=公司服务器自身未同步，反馈时间服务器管理员
```

**备选**（公司服务器不可用时，编辑 `/etc/chrony.conf` 顶部加 server 行 → `systemctl restart chronyd`）：

1. 内网有 NTP/网关：`server <内网NTP地址> iburst`
2. 可出公网：`server ntp.aliyun.com iburst` + `server ntp.ntsc.ac.cn iburst`
3. 都不行：
   - 10.60.14.14：`timedatectl set-time "YYYY-MM-DD HH:MM:SS"`（按可信时间手动校准）；chrony.conf 末尾加 `local stratum 8` 和 `allow 10.10.7.20`；`firewall-cmd --add-service=ntp --permanent && firewall-cmd --reload`
   - 10.10.7.20：chrony.conf 加 `server 10.60.14.14 iburst`

**验收**：

## 六、异常回滚

| 现象 | 回滚操作 |
|---|---|
| api 重建后异常 | 服务器上删 `.env.backend` 的 `TZ=` 行 → `docker-compose -f docker-compose.backend-run.yml up -d --force-recreate api ai-worker` |
| 门户重建后异常 | 删 `docker-compose.portal-run.yml` 锚里的 `TZ: Asia/Shanghai` 行 → `docker-compose -f docker-compose.portal-run.yml --env-file .env.fronted up -d --force-recreate` |
| 时区自检行出现 `14:30:00.000Z` | 在跑旧镜像——重新走 `部署/backend.sh` 出包 + 服务器 `backend.sh` 部署 |
| 容器 date 仍是 UTC | 未重建成功：确认用了 `--force-recreate`；`docker inspect -f '{{.Config.Env}}' <容器> \| tr ' ' '\n' \| grep TZ` 查实际注入 |
| NTP 一直 no | `chronyc sources -v` 全 `^?` = 网络不通源；换源或走一/3 兜底 |
