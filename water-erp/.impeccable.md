## Design Context

### Users
- **采购人员/开标主持人**: 长期在办公室操作，处理大量招标项目数据和审批流程，需要高效操作和数据清晰呈现
- **评标专家**: 独立评审，需要专注、干扰少的界面，AI 辅助信息需清晰标注为参考
- **供应商代表**: 外部企业人员，通过门户查看公告、投递标书、管理资质
- **管理员**: 全局视角，监督审计，关注异常和风险

### Brand Personality
- **现代活力**: 打破传统 ERP 的刻板印象，让政府企业软件也能有现代产品的精致感
- **精密工业**: 如瑞士工程制图般的精确感——细线分割、技术质感、monospace 数字
- **水利行业**: 呼应"水"的主题，蓝色系深化层次，从藏蓝到冰蓝

### Aesthetic Direction
- **视觉基调**: 精致工业风 — DIN 标准的精确感 + 瑞士平面设计的克制
- **参考**: Linear.app 的工具精确感、彭博终端的密度与节奏、日本 JIS 工业标准的美学
- **反参考**: 通用管理后台模板（大圆角卡片+渐变按钮+emoji图标）、Gmail/Material Design 风格
- **主题**: 浅色为主（办公场景、白天使用、高信息密度阅读）

### Design Principles
1. **信息密度优先**: 不为了留白而降低信息量。用排版层级而非空间间隔来区分信息。
2. **精确即是美**: 细线分割（1px hairline）、精确对齐、monospace 数字、技术质感
3. **蓝色深阶**: 从深藏蓝到冰蓝的多层次蓝色系统，配合暖灰中性色基底
4. **新拟态凸起边框**: 组件通过方向性双影（亮高光左上 + 暗投影右下）+ 内高光线浮出背景，替代传统全向投影。按钮默认外凸、悬停抬升、激活内凹。阴影色值以页面背景 `oklch(0.975 0.012 258)` 为基准推导，亮面 `oklch(1 0 0 / 0.7–0.95)`、暗面 `oklch(0.45–0.55 0.03–0.08 258 / 0.08–0.18)`。不用于文本/标签/图标等内联元素。
5. **工业图标系统**: 统一 1.5px 描边的 Lucide SVG 图标，替代所有 emoji

## Neumorphic Raised Border System

All interactive components (buttons, cards, list containers, link buttons) use directional neumorphic shadows derived from the page background.

### Color Palette
| Token | Value | Usage |
|-------|-------|-------|
| Page BG | `oklch(0.975 0.012 258)` | Shadow derivation baseline |
| Light highlight | `oklch(1 0 0 / 0.7–0.95)` | Top/left raised edge; higher opacity = more elevated |
| Dark shadow | `oklch(0.55 0.03 258 / 0.08–0.18)` | Bottom/right depth; higher opacity = stronger lift |
| Dark shadow (hover) | `oklch(0.45 0.08 258 / 0.1–0.12)` | Deeper tone on hover lift |
| Inner highlight line | `inset 0 1px 0 oklch(1 0 0 / 0.7–0.85)` | Top edge light line for card containers |

### State Pattern
| State | Technique | Example |
|-------|-----------|---------|
| **Default** | Directional pair: dark offset bottom-right, light offset top-left | `box-shadow: 2px 2px 4px oklch(0.55 0.03 258 / 0.12), -1px -1px 3px oklch(1 0 0 / 0.9)` |
| **Hover** | Lift via `translateY(-1px ~ -4px)`, stronger shadow pair | Same offsets but larger blur + higher alpha |
| **Active/Pressed** | Inset shadows: dark top-left, light bottom-right (inverted from default) | `box-shadow: inset 2px 2px 5px oklch(0.55 0.03 258 / 0.18), inset -2px -2px 5px oklch(1 0 0 / 0.6)` |
| **Container card** | Add `inset 0 1px 0 oklch(1 0 0 / 0.7)` as first shadow layer | Creates light catching the top edge |

### Anti-Patterns
- Do NOT use flat/omnidirectional `box-shadow` (e.g., `0 4px 20px rgba(...)`) — always directional pairs
- Do NOT use neumorphism on text, inline elements, tags, or badges
- Do NOT exceed dark shadow alpha 0.18 or blur > 14px — the effect should be subtle
- Do NOT mix with Material Design elevation shadows in the same component
- Neumorphic shadows on `overflow: hidden` containers will be clipped at edges

## Supplier Portal (3004) Addendum

### Supplier Users and Context

- 3004 的主要用户是正式供应商与受邀临时供应商，包括企业注册经办人、投标专员、授权代表、合同/履约人员。
- 他们在高责任、强时限、重合规的场景中完成准入、项目检索、邀请回执、采购文件获取、U 盾与双信封投标、开标确认、澄清与异议、成交通知、合同履约、目录供货和档案回看。
- 供应商门户是外部协作泳道；状态、通知、材料和操作结果必须与公共门户、采购工作台、开评标端、专家端、采购商城及统一 API 保持一致。

### Supplier Experience Principles

1. **以闭环而非页面数量衡量完整度**：每个供应商动作都要在采购方、开评标方或商城侧有承接、回执、通知和审计结果。
2. **把确定性放在首位**：截止时间采用服务器时钟；提交、撤回、签名、解密、确认和审批均展示状态、影响范围、下一步及凭证。
3. **渐进披露复杂流程**：注册、投标、资料维护等长流程按任务阶段组织，首屏突出当前必须完成的动作，同时允许回看已完成信息。
4. **真实数据与诚实降级**：不以 mock fallback 冒充业务结果；加载、空、错误、权限不足、过期和服务不可用状态分别表达并提供恢复路径。
5. **跨端语言与状态一致**：项目阶段、供应商状态、公告类型、文件名称、按钮术语和错误码使用同一语义来源。
6. **合规也要可用**：键盘、屏幕阅读器、44px 触控目标、WCAG AA 对比度、可见焦点、减少动画和错误定位是关键流程的发布门槛。
