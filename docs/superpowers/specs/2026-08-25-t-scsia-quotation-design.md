## 3. 应用边界定义（计数根本前提）

**整个"智慧水发·蜀水云采"为一个应用边界**。9 个门户是同一应用的不同交互通道（共享一个 API、一个数据库），**不是** 9 个独立应用：

- 计数以 **API 端点为主**（业务逻辑集中在 `apps/api`，44 控制器 / 673 端点）；
- 门户纯展示层不产生独立计数项；跨门户暴露的同一功能（如各门户的登录/me）只计一次基本过程；
- OCR 微服务（`services/ocr`，Python）对外暴露 REST 接口，其计数项并入系统边界内（归 AI 智能组）；
- ai-bid worker 是内部进程（无边界穿越的用户功能），其产出功能已由提交分析任务的端点覆盖，不单独计数；
- WebSocket（开标大厅实时事件）是已有基本过程的交互通道，不产生新计数项。

## 4. 计数作业规程（A2）

### 4.1 数据功能（ILF/EIF）——来自 126 个 Prisma 模型

逐模型按下表判定，产出《ILF/EIF 清单》（模型名 → 判定 → 归并后计数项）：

| 规则 | 操作 | 标准依据 |
|---|---|---|
| 纯枚举/字典表 | 剔除（代码数据实体） | C.2.1 |
| 仅外键的纯关联表 | 剔除，外键属性分组给主实体 | C.2.1 |
| 框架/技术表（会话、迁移等非用户可识别） | 剔除 | C.2.1 |
| 强依赖主从实体（明细随主档生命周期） | 归并为主实体的 RET 子组，计 1 个 ILF | C.2.1/C.5 |
| 边界内维护的用户可识别数据组 | 计 ILF | C.2.1 |
| 引用但由外部维护的数据组 | 计 EIF | C.2.2 |

**EIF 预判**：本系统自包含（外部依赖为 LLM/OCR 等服务调用，非数据组引用），预判 EIF = 0；在清单中明示举证，若盘点发现外部数据引用则如实计数。

### 4.2 事务功能（EI/EO/EQ）——来自 673 个端点

**分类判据**：

| 端点特征 | 归类 | 标准依据 |
|---|---|---|
| POST/PUT/PATCH/DELETE，维护 ILF 或改变系统行为（含登录、上传、审批、状态流转） | EI | C.3.1 |
| 输出含数学计算/衍生数据（统计、排名、汇总、报告生成、导出、AI 分析结果） | EO | C.3.2 |
| 简单提取呈现（列表、详情、下拉选项） | EQ | C.3.3 |
| 健康检查、内部探针等非用户功能 | 剔除 | — |

**C.7 归并操作定义**：

- 同资源的 list + detail（同 DET/FTR/处理逻辑）→ 归并为 1 个 EQ；
- create 与 update 处理逻辑不同 → 各计 1 个 EI；
- 同一基本过程的多端点变体（多门户同构端点、批量与单个操作的同类过程）→ 归并；
- 分页/筛选参数不产生新计数项（同一基本过程）。

产出《端点归并明细表》：端点 → 归类 → 归并组 → 基本过程名。计数先由脚本生成初始清单（grep 控制器装饰器），人工逐项判定后定稿。

### 4.3 重用度分组

| 组 | 重用度 | 依据 |
|---|---|---|
| 通用支撑模块（auth / user / company / notification / upload / audit / operation-log 等用户、角色、权限、系统管理、日志类） | **高（1/3）** | C.6 注硬性规定（常规通用模块） |
| 全部域功能（招投标、商城、专家、AI 等业务模块） | **低（1.0）** | 净新建举证：系统从零自研，无既有信息系统或共享平台处理过这些数据 |

备选（用户可改）：标准默认全中（2/3）——将使 US 下降约 1/3，在敏感性分析中给出对比。

### 4.4 子系统分组与 ST

| 子系统 | 模块归属 | ST | 依据 |
|---|---|---|---|
| 核心业务组 | bid、announcement、supplier、supplier-portal、expert、procurements、budget、catalog、progress、project-management、contacts、badge、alerts、chat、search 等 | **1.0 业务处理** | 经营管理及业务处理应用 |
| AI 智能组 | ai、ai-bid-analysis（+worker）、assistant、local-ai、knowledge、OCR 微服务 | **1.5 智能信息** | NLP、AI、专家系统 |
| 大屏组 | 供 :3010 消费的 dashboard/statistics 端点 | **1.3 多媒体** | 图表影像多媒体应用 |
| 通用支撑组 | auth、user、company、notification、upload、audit、operation-log、redis、prisma、common、scheduler、verification | **1.0 业务处理** | 管理类 |

每组单独计数、单独代入 ST（符合 C.7 注"按主体功能取值"）。模块归属在计数表中逐项标注；争议模块（如 dashboard 同时服务管理端与大屏）按主要消费方归属。

## 5. 参数表（推荐值，用户已确认）

| 参数 | 取值 | 依据 / 举证 |

| 特征 | 取值 | 证据 |
|---|---|---|
| 性能效率 | +1 | LLM 并发信号量与退避（LLM_MAX_CONCURRENCY/RETRIES）、pgbouncer 连接池、Redis 缓存 |
| 兼容性 | +1 | 9 门户跨浏览器、多角色多端适配、移动端 |

## 7. 系统集成费计取（B 主干第三项）

- 集成对象总费用 = **定制软件开发费**（硬件设备购置费 = 0、成品软件购置费 = 0：全栈开源，开源软件不计购置费）；
- 软件集成费率取上限 **8%**：跨 9 门户 + API + worker + OCR + WebSocket 实时的多系统集成为真实发生的实施工作；
- 调整系数 **1.0**（非涉密项目；采用国密算法 ≠ 涉密项目）；
- 系统集成费 = SDC × 8% × 1.0。
