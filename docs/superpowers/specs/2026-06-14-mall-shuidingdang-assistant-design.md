# 电子商城水叮当助手重做设计

日期：2026-06-14

## 背景

电子商城当前“智能采购价格助手”以页面卡片形式展示 `可参考 / 需询价 / 将过期 / 待复核` 四个统计值，并提供一个简单 AI 输入框。这组数字来自目录条目的状态与价格波动统计，但对用户当前采购动作帮助有限：它不能直接说明当前要采购的条目是否可引用、哪些需要复核、下一步应做什么。因此，本次改造将其重做为电子商城内的“水叮当”智能助手。

目标是参考 `/Users/qihao/Desktop/procurement` 中水叮当的设定与实现风格，保留统一的角色资产、头像和对话体验，但不完整移植其复杂的会话历史、SSE、工具调用和后端 assistant 体系。电子商城需要一个页面级、轻量、定制化的水叮当。

## 已确认决策

- 采用“页面内搜索栏式入口 + 居中弹窗对话窗口”。
- 不做右下角悬浮入口。
- 不做常驻右侧助手卡。
- 不保留当前 `可参考 / 需询价 / 将过期 / 待复核` 四个统计块作为核心展示。
- 水叮当定位为：优先价格参谋，同时支持预算清单建议和商城导购。
- 头像沿用 procurement 项目中的水叮当角色资产与表情体系，不能使用廉价水滴、emoji 或临时图形作为最终头像。
- 弹窗 header 只显示水叮当头像和“水叮当”，不显示副标题。
- 欢迎页采用简约风格；仅当用户已有筛选条件或预算清单时显示一行轻量上下文。

## 目标体验

用户在电子商城页面中看到一条简约的水叮当搜索/提问栏。该入口替代当前顶部“智能采购价格助手”区域。

入口应包含：

- 水叮当角色头像。
- 标题：`水叮当 · 电子商城价格参谋`。
- 输入框提示：`问水叮当：分析当前筛选结果、找出需复核价格、生成预算清单建议`。
- 右侧按钮：`问水叮当` 或 `开始分析`。

用户点击输入框、按回车或点击按钮后，打开居中对话弹窗：

- 若用户已输入问题，则打开后自动发送该问题。
- 若用户未输入问题，则展示简约欢迎页。
- 对话过程不离开当前目录页面。
- 关闭弹窗后，会话可保留在当前页面状态中，刷新后不保留。

## 弹窗设计

弹窗采用居中 Modal：

- 桌面端建议尺寸约 `720px × 620px`。
- 移动端接近全屏。
- Header 左侧显示水叮当头像 + `水叮当`。
- Header 右侧显示关闭按钮。
- Header 不显示任何副标题。
- 内容区展示欢迎页、消息列表或 loading 状态。
- 底部为输入框和发送按钮。
- 支持 Enter 发送；如实现成本允许，Shift+Enter 换行。

### 欢迎页

欢迎页保持克制、简约，不做数据看板：

- 水叮当头像。
- 问候语：`你好，我是水叮当`。
- 能力说明：`我可以帮你研判目录价格、生成预算建议、比较供应商报价。`
- 有上下文时展示一行轻量提示，例如：`我会结合当前筛选：管材 / 全省 / 有效价格，以及预算清单 3 项来回答。`
- 无筛选、无预算清单时不显示上下文提示。
- 快捷问题最多 3 个：
  1. `分析当前筛选结果`
  2. `找出需复核价格`
  3. `生成预算清单建议`

欢迎页不展示大面积统计卡、风险仪表盘、图表或复杂说明。价格风险类信息应在用户提问后由水叮当生成。

## 问答能力边界

水叮当在电子商城中重点回答：

- 当前筛选结果研判。
- 单个目录条目价格研判。
- 需复核/需询价条目识别。
- 预算清单建议。
- 供应商价格区间对比。
- 商品规格、分类、供应商导购。
- 审计说明口径，例如“为什么这条价格不能直接引用”。

回答结构应结论先行：

1. 结论：这批价格能否参考、是否建议询价、是否需要复核。
2. 依据：引用当前目录上下文，如价格来源、区间、历史均价、有效期、变化率。
3. 建议动作：加入预算、二次询价、复核维护、对比供应商、调整筛选。
4. 注意事项：不替代审批、不决定最终成交价、不指定成交供应商。

水叮当不应：

- 决定中标供应商。
- 要求或建议绕过审批、复核、询价流程。
- 扩展回答与电子商城无关的招标评审、专家评分、供应商资质审查。
- 在没有上下文时编造市场价格、供应商报价或审批结果。

## 提示词设计

`apps/mall/src/app/api/ai/route.ts` 中的 system prompt 应改为电子商城水叮当专属提示词。建议要点如下：

```text
你是四川水发集团电子商城中的“水叮当”，负责集中采购目录的价格参谋能力。

你的职责：
- 帮助采购人员研判目录价格是否适合用于预算参考。
- 帮助识别需要复核、询价或比价的条目。
- 帮助基于目录数据生成预算清单建议。
- 帮助比较供应商价格区间、价格来源、有效期和价格变化。
- 帮助形成可用于内部沟通或审计说明的简洁口径。

回答要求：
- 必须使用中文。
- 风格专业、简洁、可执行。
- 结论先行，再说明依据和建议动作。
- 优先基于传入的当前筛选条件、可见目录条目、预算清单和商品详情回答。
- 数据不足时说明缺少什么，不要编造市场行情、供应商报价或审批结果。
- 不替代审批，不决定最终采购价，不指定成交供应商。
- 与电子商城无关的问题应简短说明超出当前模块范围，并引导用户回到目录价格、预算、询价或供应商比价场景。

建议输出结构：
结论：
依据：
建议动作：
注意事项：
```

针对常见问题类型的回答重点：

- `分析当前筛选结果`：总结可引用条目、需询价条目、需复核条目，并给出处理顺序。
- `找出需复核价格`：列出高风险条目，说明触发原因，如价格波动、即将过期、状态待复核。
- `生成预算清单建议`：基于当前可见条目和预算清单给出条目、数量确认点、估算金额和注意事项。
- 单品研判：围绕参考价、价格区间、历史均价、供应商、来源、有效期、变化率给结论。
- 供应商比价：比较价格区间和供应商覆盖，但不直接指定中标或唯一供应商。

## 组件设计

在 `apps/mall` 内新增轻量 assistant 组件组，避免把 procurement 的完整 assistant provider、历史会话、SSE 和工具调用体系直接搬进 ERP。

建议组件：

### `MallAssistantEntry`

页面中的水叮当搜索栏入口。职责：

- 替代当前顶部“智能采购价格助手”区域。
- 管理入口输入内容。
- 点击、回车或按钮触发弹窗。
- 将初始问题传给弹窗。

### `MallAssistantDialog`

居中 Modal。职责：

- 管理打开/关闭。
- 管理消息列表、loading、错误状态和输入框。
- 初始问题存在时自动发送。
- 渲染 header、欢迎页、消息列表和底部输入区。

### `MallAssistantWelcome`

极简欢迎页。职责：

- 展示水叮当头像、问候语、能力说明。
- 根据上下文决定是否展示一行轻量上下文提示。
- 渲染最多 3 个快捷问题。

### `MallAssistantMessage`

消息气泡。职责：

- 展示用户消息和助手消息。
- 支持普通文本换行。
- 不需要复杂 Markdown 渲染，除非项目已有合适依赖。

### `MallAssistantAvatar`

水叮当头像组件。职责：

- 复用 procurement 项目中的水叮当角色资产与表情资源。
- 至少支持 `normal`、`thinking`、`serious` 三种状态。
- 不使用临时水滴、emoji 或低质图形。

## 数据流

`apps/mall/src/app/page.tsx` 负责构造电子商城上下文，并传给水叮当组件。

上下文包括：

- 当前筛选条件：分类、区域、状态、来源、搜索词。
- 当前可见条目：限制传前 12 条，避免 prompt 过长。
- 当前预算清单：条目名称、数量、单位、参考价。
- 当前风险摘要：作为 AI 参考，不在入口展示。
- 当前选中商品：如果用户从商品详情中发起研判，则带入该商品。

调用链：

```text
MallAssistantDialog
  -> POST /api/ai
  -> DeepSeek chat completion
  -> 返回 answer
  -> 追加到消息列表
```

本次不做：

- 服务端会话历史。
- SSE 流式输出。
- 工具调用。
- 数据库存储对话记录。
- 跨页面全局助手。

## 交互细节

- 用户在页面搜索栏输入问题并回车或点击按钮：打开弹窗并自动发送该问题。
- 用户点击页面搜索栏但不输入：打开弹窗并展示欢迎页。
- 用户点击欢迎页快捷问题：直接发送对应问题。
- 用户在商品详情中点击“让水叮当研判”（如保留或新增该入口）：打开弹窗并自动发送该商品价格研判问题。
- AI 回答完成后：输入框保留，可继续追问。
- 关闭弹窗后：当前会话保留在页面状态中，刷新后清空。

## 错误处理

- 未配置 `DEEPSEEK_API_KEY`：弹窗内显示 `水叮当暂未启用，请联系管理员。`
- DeepSeek HTTP 错误：弹窗内显示 `AI 服务暂时不可用，请稍后重试。`
- 空问题：不发送请求，保留欢迎页或提示用户输入问题。
- 数据不足：由 prompt 要求水叮当说明缺少哪些数据，而不是编造。
- Loading：入口按钮显示处理中；弹窗内显示 `水叮当思考中`。

11. 运行 mall lint/build，确认无类型错误。

## 范围外

以下内容不纳入本次实现：

- 完整移植 procurement 的 assistant 后端模块。
- 聊天历史持久化。
- 多会话管理。
- SSE 流式输出。
- 工具调用与自动操作。
- 跨页面全局助手。
- 招标评审、专家评分、供应商资质审查等非电子商城能力。
