## 1. 背景与动机

专家向导 ④ 打分、⑤ 写理由时常需引用 ③ 核对里写过的异议/疑问备注。系统**已有一套手动机制**：类别顶部只读「异议备注」列表 + 每个评分项的「📎 插入异议」按钮（点开列表 → 逐条点「插入」）。痛点：两段式手动，且只覆盖 `dispute`、不含 `doubt`。

本设计把它**改造合并**：聚焦理由框时同一个备注面板自动展开 + 复选框勾选追加；保留「📎」按钮作为手动开关（两条路开同一个面板）；覆盖范围从 dispute 扩到 dispute+doubt。守住「专家独立落字」——备注仅作可勾选素材，绝不自动落分或裁定。

## 2. 目标 / 非目标

**目标**
- 聚焦理由框 → 备注面板自动展开；「📎 插入异议」按钮也能手动开关**同一个**面板
- 复选框勾选 → 按格式 ② 追加进理由框（幂等，不重复）
- 覆盖 `dispute` + `doubt`（现状仅 dispute）
- 复用现有 `disputesBySupplier` 数据通路，**不新增字段、不改路由**

**非目标（MVP 外）**
- LLM 合成理由
- 自动把资格审查异议判为「不通过」
- 跨供应商批量引用
- 改动异议软门（`disputeCategoriesBySupplier` + `confirmedDispute` 行为不变）

## 4. 数据 / API 变更（改造现有）

扩展 `getMyScores` 的 `disputesBySupplier`（**不改路由、不新增字段**）：

- 查询 `verdict: 'dispute'` → `verdict: { in: ['dispute', 'doubt'] }`
- 每个 item 增加字段 `verdict: 'dispute' | 'doubt'`（供前端徽标区分）
- item 形状变为 `{ requirementId, content, note, verdict }`
- `disputeCategoriesBySupplier`（软门用）**保持 dispute-only 不变**
- 抽公共方法 `buildExpertReviews(projectId, expertId, verdicts)`：`getMyScores`（disputesBySupplier 用 `['dispute','doubt']`；disputeCategoriesBySupplier 仍单独按 `['dispute']` 聚合）与 `getReport.myDisputedReviews`（`['dispute']`）复用，消除两处反查重复

## 5. 前端变更（改造现有机制，`page.tsx`）

**保留不动**：类别顶部只读「异议备注」列表（:1121-1135）；`disputeCategoriesBySupplier` / `confirmedDispute` 软门逻辑。

**改造**：每评分项的「📎 插入异议」区块（:1168-1203 / :1238-1268）→ 合并为统一 `ReviewNotePanel`：

- **可见性**：该 category 在 `disputesBySupplier[activeSupplier]` 中有任意 dispute/doubt 条目时显示（不再只 gate 于 dispute-only 的 `disputed`）。
- **展开触发（两条路开同一个面板，单一 `reviewPanelOpenKey` state）**：
  - 聚焦该理由框 → `setReviewPanelOpenKey(k)`
  - 点「📎」按钮 → toggle `reviewPanelOpenKey`（k↔null）
  - 失焦：`setTimeout(0)` 检查 `suppressBlur`，false 则清 key，true 则复位
- **列表项**：复选框（`onMouseDown` 置 `suppressBlur=true`）+ 预览（verdict 徽标「异议/疑问」+ content 简摘 40 字 + note 首行）。
- **勾选（方案 A，追加式，专家接管）**：`insertedKeys: Set<noteId>`，`noteId = ${supplierId}:${requirementId}`
  - 勾选且未插入 → 追加格式块到 `scores[k].reason`（原非空换行）；入 set
  - 取消勾选 → 不动 reason；复选框灰显「已插入」
- **格式块（②，无 verdict 前缀）**：`【★条款 {requirementId}：{content 截断 40 字}】{note}`（note 空则用 content 兜底）
- 锁定（`scoreLocked`）：面板不渲染

**移除**：旧「插入」按钮及其 onClick（:1184-1197 / :1254-1265）。

## 6. 边界处理

| 场景 | 处理 |
|------|------|
| verdict 范围 | dispute + doubt（ack 不计） |
| note 空串 | 用 content 兜底（沿用现有逻辑） |
| content 缺失 | 显示「(原文缺失)」 |
| 切供应商 | `noteId` 含 supplierId → `insertedKeys` 天然隔离；切时清 `reviewPanelOpenKey`（与现有 `setConfirmedDispute({})` 同处补） |
| pass-fail 通过态 | 无理由框 → 无面板（仅「不通过」后理由框聚焦才出） |
| doubt-only 类别 | 面板显示，但软门（dispute-only）不拦 |
| 报告已确认 | 面板不渲染 |

## 8. 测试

**后端单测（`expert.service.spec.ts`）：**
- `disputesBySupplier` 含 dispute + doubt，ack 不进
- 每个 item 带 `verdict`；`content` 反查正确、缺失兜底
- `disputeCategoriesBySupplier` 仍 dispute-only（软门不变）
- `getReport.myDisputedReviews` 改用公共方法后仍仅 dispute、行为不变

**前端手测：**
- 聚焦理由框 → 面板展开 → 勾选 → 追加 → 再勾不重复
- 「📎」按钮也能开关同一面板
- 切供应商 → 面板内容切换、插入态隔离
- doubt-only 类别：面板显示、软门不拦
- pass-fail「不通过」→ 面板；RESPONSIVE/PRICE 无面板
- 报告确认 → 面板不渲染

## 9. 风险 / 注意

- **合规**：备注仅作可勾选素材，绝不自动落分或裁定通过/不通过。
- **焦点时序**：textarea onBlur 与复选框点击时序用 `suppressBlur` defer 规避（复选框 `onMouseDown` 预置）。
- **软门/面板解耦**：软门 dispute-only、面板 dispute+doubt，避免 doubt 误触软门。
