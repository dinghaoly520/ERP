# 开评标系统板块设计文档

日期：2026-06-05

## 目标

在现有“智慧水发·蜀水云采”招采 ERP 前端中新增一个演示级完整闭环的“开评标系统”板块。系统以“统一入口、多端协同、安全可控、限时开标、独立评审、全程留痕”为核心，覆盖企业安全组件、招标文件受控下载、投标文件加密投递、在线开标解密、专家独立评审、监督审计和资料归档。

本期实现定位为前端演示级完整闭环，不接真实后端，不实现真实加密、CA、电子签章、文件上传存储或权限系统，但页面结构、状态模型和交互文案要贴近真实业务流程，便于后续接入接口。

## 当前项目背景

项目当前包含两套前端形态：

1. 根目录静态门户页，例如 `index.html`、`bid.html`、`css/bid.css`、`js/bid.js`。
2. `supplier-vue` Vue 管理端，使用 Vue 3、Vue Router、Pinia、Element Plus。

现有 Vue 端已有 `开评标管理` 一级菜单，但只注册了 `/bid` 路由；侧边栏中已有 `/bid/open`、`/bid/system`、`/bid/result` 等入口，但路由未完整实现。现有 `supplier-vue/src/views/bid/Index.vue` 仅包含基础投递、开标列表、投标系统占位和结果公示表格，尚未形成完整开评标业务系统。

## 总体方案

采用“静态门户介绍 + Vue 业务系统”的双端结构。

### 静态门户

`bid.html` 保持对外展示定位，增强为完整的开评标系统介绍页。它展示系统建设定位、核心能力、业务流程、安全机制、角色协同和入口按钮，不承担复杂业务操作。

门户页需要突出以下能力：

- 企业唯一安全组件。
- 招标文件受控下载。
- 投标文件加密上传。
- 开标时间前密文保存，不可下载、预览或解密。
- 到时开标、在线解密、自动生成开标记录。
- 专家独立评标、评分校验、报告生成。
- 监督可见不可干预。
- 过程留痕和资料归档。

### Vue 管理端

Vue 端作为演示级业务系统，采用“角色工作台”组织方式。每个角色拥有独立页面，体现多端联动和权限边界。

路由规划：

- `/bid`：开评标总览驾驶舱。
- `/bid/submit`：供应商端。
- `/bid/open`：开标主持端。
- `/bid/evaluate`：专家评标端。
- `/bid/supervise`：监督端。
- `/bid/archive`：归档端。

## Vue 页面设计

### `/bid` 开评标总览驾驶舱

总览页展示同一批项目在各环节的整体状态。

内容包括：

- 指标卡片：待开标项目、密文投递数、解密成功率、评审完成率、归档完整率。
- 流程链路：插件授权、文件下载、加密投递、到时开标、专家评标、报告归档。
- 项目列表：项目名称、编号、开标时间、投标单位数、当前阶段、风险状态、推荐进入的工作台。
- 风险提醒：插件异常、解密超时、专家未签到、评分漏项、归档缺项。
- 角色入口：供应商端、开标主持端、专家评标端、监督端、归档端。

### `/bid/submit` 供应商端

供应商端模拟从安全组件到投标回执的流程。

内容包括：

- 企业唯一安全组件卡片：企业编号、插件授权号、插件版本、授权设备数量、证书状态。
- 下载前置条件：企业审核、项目报名、插件激活、设备授权、项目下载窗口。
- 招标文件下载控制：展示水印文件、下载日志、文件哈希、下载时间。
- 投标文件加密投递：文件选择、签章状态、哈希校验、加密状态、上传进度、提交回执。
- 截止锁定提示：投标截止后关闭上传、替换、撤回入口。

所有上传和下载操作均为前端模拟交互，显示真实业务文案和状态反馈。

### `/bid/open` 开标主持端

开标主持端模拟在线开标大厅。

内容包括：

- 项目开标信息：项目名称、开标时间、投标截止时间、解密时间窗口、主持人、监督人。
- 开标倒计时或当前状态。
- 投标单位解密状态表：待解密、解密中、成功、超时、异常。
- 主持操作：开始开标、发送解密提醒、锁定投标文件、生成开标记录。
- 开标记录：投标单位、报价、工期或服务期、质量目标、保证金状态、解密结果、确认状态。
- 异常处理：区分投标人原因和平台原因，展示处理意见和证据留痕。

### `/bid/evaluate` 专家评标端

专家评标端采用三栏式工作台，强调独立评审和评分规范。

内容包括：

- 进入前置步骤：身份核验、保密承诺、回避确认、评标纪律确认。
- 左侧投标单位列表：单位名称、资格审查状态、符合性状态、评分完成状态。
- 中间文件阅读区：招标文件、投标文件摘要、资格文件、技术响应、商务响应、报价信息。
- 右侧评分区：资格性审查、符合性审查、商务评分、技术评分、价格评分、评分理由。
- 评分校验：漏评、超分、未填理由、偏差过大提示。
- 澄清与说明：发起澄清、供应商回复、处理意见。
- 报告确认：评分汇总、中标候选人、专家电子确认模拟。

普通专家页面不展示其他专家的具体评分，避免破坏独立评审原则。演示中可展示“本人进度”和“汇总后结果”。

### `/bid/supervise` 监督端

监督端强调“可监督、不可干预”。

内容包括：

- 开评标节点时间线。
- 投标文件上传与锁定记录。
- 解密记录。
- 专家签到、承诺、回避确认记录。
- 评分提交与评分修改记录。
- 澄清记录。
- 异常事件列表。
- 日志查询和导出模拟按钮。

监督端不提供修改评分、替专家提交意见、开标前下载明文投标文件等操作。

### `/bid/archive` 归档端

归档端展示资料闭环。

内容包括：

- 归档完整率。
- 电子档案编号。
- 防篡改摘要。
- 资料清单：招标文件、下载日志、投标回执、文件哈希、开标记录、专家签到表、评分表、澄清记录、评标报告、结果公示。
- 缺失资料提醒。
- 一键归档演示操作。

## 数据设计

新增 `supplier-vue/src/stores/bid.js`，集中管理演示数据，避免数据分散在各页面。

核心 mock 数据包括：

- `projects`：项目编号、名称、采购方式、开标时间、投标截止时间、当前阶段、风险等级。
- `securityComponent`：企业编号、插件授权号、插件版本、设备数量、证书状态。
- `suppliers`：供应商名称、报名状态、下载状态、投递状态、加密状态、回执号。
- `openingSession`：开标状态、解密窗口、主持人、监督人、解密统计。
- `openingRecords`：报价、工期、质量目标、解密结果、确认状态。
- `experts`：专家姓名、专业、签到状态、承诺状态、回避确认、评分进度。
- `scoreItems`：资格性、符合性、商务、技术、价格评分项。
- `clarifications`：澄清问题、发起人、供应商回复、处理状态。
- `supervisionLogs`：操作时间、角色、操作对象、操作结果、风险标记。
- `archiveItems`：资料名称、责任角色、归档状态、哈希摘要、归档时间。

## 视觉风格

继续沿用现有“智慧水发”蓝白风格：

- 主色：`#064ea2`。
- 深蓝：`#042a58`。
- 成功绿：`#11a874`。
- 预警橙：`#f5a623`。
- 异常红：`#e74c3c`。
- 页面背景：`#f6f9fd`。
- 卡片边框：`#e8f0fa`。
- 卡片圆角：`8px`。

Vue 端优先使用 Element Plus 的表格、表单、标签、步骤条、时间线、进度条、上传组件和对话框。评标端采用三栏布局，开标端采用大厅式状态面板，监督端采用时间线和日志表格。

## 交互原则

- 开标时间前，页面只展示密文状态、上传回执和统计数量，不展示投标文件明文。
- 供应商只能看到本企业相关状态。
- 专家必须完成身份核验、保密承诺、回避确认后才能进入评分界面。
- 监督端只能查看状态、日志和异常，不提供干预性操作。
- 所有关键操作都产生模拟日志。
- 评分提交前做前端校验，包括漏评、超分、未填理由。
- 归档端按资料清单展示完整性和缺失项。

## 不在本期实现

- 真实后端接口。
- 真实文件上传、存储、断点续传。
- 真实文件加密、CA、电子签章、可信时间戳。
- 真实身份认证和权限校验。
- 实时 WebSocket/SSE。
- AI 辅助评审。
- 与 OA、合同、档案、电子保函等系统对接。

这些能力通过页面结构、状态文案和 mock 数据预留展示，不做真实技术实现。

## 验证计划

实现完成后执行：

1. 检查 Vue 端依赖和脚本。
2. 启动 Vue 开发服务。
3. 在浏览器中手动访问并验证：
   - `/bid`
   - `/bid/submit`
   - `/bid/open`
   - `/bid/evaluate`
   - `/bid/supervise`
   - `/bid/archive`
4. 检查静态 `bid.html` 展示和入口跳转。
5. 如项目脚本可用，运行构建命令验证无编译错误。

## 验收标准

- 静态门户能清晰说明开评标系统能力，并能进入 Vue 端。
- Vue 端侧边栏的开评标子菜单均能打开真实页面。
- 六个 Vue 页面围绕同一 mock 项目形成完整业务闭环。
- 页面能体现安全组件、限时开标、密文投递、在线解密、专家独立评审、监督不可干预、资料归档等核心规则。
- 没有明显路由错误、控制台编译错误或页面空白。
- 代码结构便于后续替换为真实 API 数据。
